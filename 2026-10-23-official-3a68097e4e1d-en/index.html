Tencent Hy-Nomas Open Weights: What kind of interactive video world can an RTX 4090 run?

Oct 23, 20265 min read
简体中文English
Categories:Tech
Tags:#AI#Frontier models
Summary

Hy-Nomas has opened up model assets and offered a single-card RTX 4090 solution, but local running still has barriers.

Info: Machine translation This post was machine-translated from the Chinese original. Wording may be rough in places — the Chinese version is authoritative.

To keep adding objects, changing scenes, and then having shots move along a specified path during generation, it used to require regenerating or stitching multiple clips. Tencent Hy-Nomas aims to solve the problem of allowing the same video world to develop continuously with text and camera commands.

The most noteworthy aspect is not a demo image, but two entry points already in place: Hy-Nomas official model page lists model assets and offline inference explanations, and also provides configurations for a single NVIDIA GeForce RTX 4090. However, “single-card support” only means the official provides a runtime; it does not mean ordinary graphics cards can run it, nor has the generation speed independently verified.

It does not generate a blocked video

Hy-Nomas generates worlds by segments. Each round allows users to continue inputting subjects, actions, appearances, styles, and environmental changes, and can also provide camera trajectories to change observation positions and movements. The official calls this ability free-form multi-turn interaction.

You can think of it as a continuous conversation in WeChat: the later message doesn’t open a new chat window, but continues from the previous context. Hy-Nomas also generates segments one by one, preserving the context of the previous segment through KV caching. This analogy only explains “how to continue generation”; The model does not truly understand a world because of this, and its continuity is still affected by caching, prompts, and generation errors.

  • Text can incorporate objects, actions, or scene changes in subsequent clips.
  • Camera trajectories can control the viewing angle and movement along with text conditions.
  • The same world can continue to expand without starting from a completely blank state each time.
  • The distillation inference configuration uses 8 DiT denoising steps, with default outputs of 720 × 1280, 24 FPS.

Weights are listed, but “Open” does not equal “One-Click Run”

The official model page lists assets such as distilled DiT, INT8 quantized DiT, base autoregressive DiT, DCAE-v, PixelUMM decoder and its FP8 version, and notes that DiT, VAE, and PE directory structures should be retained in the repository. Standard offline inference also requires matching PixelUMM checkpoints and Qwen/Qwen2.5-VL-7B-Instruct text encoders.

The model uses the Apache License 2.0, but third-party models and components are still subject to their respective licenses. Therefore, being able to download Hy-Nomas files only addresses the “file openness” layer; Whether the license, runtime environment, supporting components, and hardware are appropriate still need to be checked separately.

The standard plan and the single-card plan do not have the same set of costs

The standard configuration uses 8-way sequential parallelism and distributed PixelUMM decoding, with eight GPUs in the same inference group by default. The official recommendation is to use a pre-packaged Docker environment; manual installation requires Linux, Python 3.12 or above, CUDA 13.0, C++ compiler, and the corresponding PyTorch and attention kernel.

The single-card configuration is designed for an NVIDIA GeForce RTX 4090: DiT weights and KV storage use INT8, decoder uses FP8, and the text encoder, DiT, and decoder are transferred between CPU and GPU in processing phases. It changes serial parallelism to sp_size=1, while retaining default settings like 720 × 1280, 24 FPS, and 8-step DiT denoising.

Warning The official statement does not describe “single RTX 4090” as light operation. System memory must accommodate unloaded models and continuously growing historical archives; peak VRAM is also affected by resolution, current fragment length, and selected configuration. The official clarification clearly states that the 18-frame historical budget only limits historical context and does not limit current fragment usage.

KV caching keeps the world connected and also leaves a bill

KV caching can be analogous to a courier station storing pickup records: when a new package arrives, the system can check previous records without having to re-register all information. Hy-Nomas reuses the attention keys and values of previous segments when generating the next segment, allowing new segments to reference the generated history.

Saving records also takes up space. Standard configurations retain complete history; the longer the world is generated, the more cache memory may increase; Single-card configurations limit active GPU history to a certain range, but earlier content is still archived to the CPU. This reduces GPU side pressure but cannot eliminate system memory growth and data transfer latency.

Online demos, offline reasoning, and review suites should be viewed separately

Online demonstrations use a separate Nomas-PE service to convert user instructions into structured prompt generation; Offline inference can directly read prepared prompt files. Nomas-PE is a standalone service required for web presentations, so the official so-called single-GPU video inference cannot be directly expanded to “a complete web service requiring only one card.”

The official Hy-Nomas-Bench has also been released, containing four benchmarks and 280 test cases, covering multi-round free-text interaction, camera navigation, text-to-camera interlacing control, and spatial memory. The current materials describe the test scope and data structure but do not provide results for independent cross-evaluation, so it cannot be inferred that it has outperformed other video world models.

Now is the right choice to choose

  • Just look at the interaction first: you can use the official online demo to observe whether continuous clips, text edits, and camera controls meet the task requirements.
  • Prepare for local deployment: First, confirm that Linux, NVIDIA drivers, Docker or CUDA 13.0 environments, model assets, and Qwen text encoders are complete.
  • Only one RTX 4090: using official single card configuration and matching INT8 DiT and FP8 PixelUMM, standard checkpoints cannot be mixed arbitrarily.
  • Long-term generation is required: focusing on recording system memory, peak video memory, single-segment time, historical growth, and continuity changes; This data cannot currently be directly derived from configuration instructions.
  • Using LoRA: The official instructions state that the INT8 loader does not support loading LoRA separately during inference. Before selecting the solution from the menu, confirm whether an adapter is required.

Hy-Nomas has already moved beyond the stage of “only concept demos, no model assets,” and has provided a clear inference path for the RTX 4090. It is more suitable for users willing to handle Linux, quant checkpoints, CPU offloading, and multi-component dependencies; If you expect an ordinary computer to generate an infinitely long world with one click, current official materials do not support this judgment. The next truly useful acceptance step is not to review the sample again, but to record on the target machine whether it can start, time spent per segment, memory growth, camera control accuracy, and whether the world remains consistent after multiple rounds of modifications.
