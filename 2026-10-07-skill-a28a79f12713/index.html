让代码画出能动的艺术风格

想让一幅水墨画动起来，最容易想到的是把整张图交给视频模型。huashu-art-motion 换了个做法：场景、物件、镜头和转场由代码控制，人物再按需要使用授权角色帧或生成素材。像搭一个小舞台，先决定谁动、什么时候动、观众看哪里，再选择画风。这样哪些动作可以反复调整，会比只等一次生成结果更清楚。

它能交付什么

作者提供了 35 张风格配方卡，并配有场景与转场代码。水墨、敦煌、皮影和点彩等风格，分别有自己的颜色、形状和运动方法。这里的配方卡像菜谱：告诉执行任务的助手怎样组合元素，不是把风格名写进提示词就算交付。本次只核验了仓库文档与文件，没有运行这些代码，实际效果仍需试渲。

另外有 9 种解说动画表达方法，其中 8 种附带按参数渲染的片段，包含白板、动态文字和财经图表等。比如解说正在解释两组数据差距，图表就应在这一句出现并完成比较，而不是整段只有背景在晃。参数文件相当于镜头清单，记录内容和时机；第 9 种讲解员式财经科普需要自备角色，不能把所有路线当成同样齐全的现成模板。

它怎么把动画拆给你

做解说动画时，作者要求先写镜头表，再定画风、安排镜头，最后输出画面。纯配乐动画则按音乐节拍安排动作，就像舞台表演踩着拍子换场。长卷穿越片用一条连续画布组织不同画风。这几条路线服务不同任务：先选你要解释的内容，再读对应方法，比把所有效果同时塞进短片更容易控制。

交付前它自己量什么

SKILL.md 写明：交付前必跑 uv run scripts/qa.py --project <工程>，验收维度是稳定 / 动感 / 流畅 / 文字框景线索，再派一个没参与制作的 agent 只看成片挑问题；浅底无字幕的成片还要再用 subzone_gate.py 检查图形是否进入字幕区。它对“画面必须动”有硬门槛：每一幕至少一个主动作加 2 个母题循环，并要量帧差避开转场后 0.35 秒的镜头冲击。

代码、字体和角色各归各家

许可证是 MIT，但有几处例外要分清：仓库里笔顺衍生数据 reference_films/spacex/spacex_wb/assets/strokes.js 沿用 Arphic Public License；scripts/engine/lib/fonts/ 里的字体沿用各自 SIL OFL 许可；花叔的卡通角色帧、示范视频和总览图里出现的同一形象，“只用于本 skill 的示范，不随 MIT 授权用于其他用途”。这意味着把人物移到自己项目里之前，需要替换或自备角色资产。

它要先装什么才能跑

作者列出的环境包括 uv、FFmpeg 和 Playwright Chromium：分别负责准备运行环境、处理视频，以及驱动浏览器里的画面渲染。安装入口是 npx skills add alchaincyf/huashu-art-motion。这是会下载并安装第三方代码的命令，先检查来源与权限，再按仓库说明安装；本次没有执行它，也没有验证不同电脑和客户端的运行表现。初次尝试可先输出一个场景的静帧，再做短片，避免直接开长工程。

哪些事你仍然要自己做

人物有不同处理方法。已有授权角色帧可以直接作为素材；需要新人物造型时，可以调用生图模型制作连续姿态，再由代码换帧合成，像翻动连环画；简单几何角色则可直接用代码绘制。因此，外接生图并不是所有动画都必须付费的步骤。具体要不要花钱，取决于角色来源、生成服务与额外素材；角色授权和连续画面的形象一致性仍要自己检查。

作者把样片当作“能做到”，不是“已通过”

README 提到这支 skill 来自对 X 用户 Tak（@cherry_mx_reds）一支 15 秒“Art History Speedrun”的真实复刻（仓库写明日期为 2026-10-04），仓库里不含原片的帧、截图或音频，场景构图沿用原作思路，所有画面用代码重画，作者另外做了一支 2 分 08 秒的《花叔穿越名画》展示 23 种画风。但仓库给的判定本身仍是“作者声明/作者样片”，不是第三方或我们这边的独立复跑。

现在能做什么，还不能做什么

如果你已在用能执行代码的 AI 助手，这个项目值得研究的是怎样把镜头、动作与画风写成可调整的工程。自备授权素材，或先选几何角色，可以减少对云端生图的依赖。但我们目前掌握的是作者文档、代码结构与样片说明，不是独立完成的成片；实际渲染耗时、错误恢复和客户端兼容性还不能下定论。

下一步怎么验收

第一次不必把 35 种画风全试一遍。拿一小段已有解说录音，选一种能帮助理解的风格，安排一个明确动作，再检查：画面有没有解释这一句，运动是否流畅，字幕位置有没有被遮住。程序检查只能发现部分技术问题，正常速度看完短片，仍是必要的一步。它更适合愿意调整工程、把艺术表达接到真实讲解上的人；只想输入一个风格名便免费得到整片的人，先别把它当成现成的视频生成网站。

建议 代码采用 MIT 许可证，人物、字体与部分衍生数据另有条款。作者示范人物不能因仓库开源就直接搬进自己的作品；制作前先检查并替换为有权使用的素材。
