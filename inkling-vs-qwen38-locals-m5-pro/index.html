Inkling 2 Mini 换上 Locals 引擎：M5 Pro 十维实测反超 Qwen3.8，唯独这一项直接撞墙

摘要

同台 M5 Pro 64GB 对比 Qwen3.8-27B 原语版、Inkling 原版 oMLX 与 Inkling Locals NVFP4 三套方案：七项非视觉实测 Locals 常规工程快出将近一半（T7 双交付 4 轮 270.7 秒），唯独重逻辑 T5 撞满思考上限，方寸智匣 2.4.5 已同步补齐大工具集适配与去重。

摘要 Qwen3.8-27B 原语版（Splash + DFlash2）、Inkling-2-Mini 原版（oMLX 0.8.2 视觉完整版）与 Inkling-2-Mini-Locals（Locals NVFP4 + 0.64 GB 草稿极速版）三方全量对比：补齐全部 7 项非视觉同题加赛与 5 题文字答案质量核验，一次讲清速度反转、大工具集避坑与各自真实边界 黑粉科技 · 2026-11-23

　　同一台 Apple M5 Pro 64GB 统一内存 MacBook Pro、同一套「方寸智匣 LocalBrain」原生代理测试台，我把最近端侧最受关注的三套越狱主力方案拉到同一起跑线上打完了全套实测——Qwen3.8-27B 越狱版（orcarouter/Qwen3.8-27B-Uncensored-MLX，运行于 Splash 1.7.0 + DFlash2 块投机解码）、Inkling-2-Mini 原版（TokenAI-zer/Inkling-2-Mini-Uncensored-oQ4-mtp，运行于独立固定版 oMLX 0.8.2）、以及换装开源极速引擎 Generated-Computers/Locals 的 Inkling-2-Mini-Locals（NVFP4 + 0.64 GB 草稿模型 + GPU 语法锁）。

　　结果非常有意思：没有谁能一张表通吃全场，反而是同一颗 Inkling-2-Mini 在换上 Locals 引擎后直接拆出了截然不同的两副面孔——原本在 oMLX 上跑 T7 双交付要磨 10 轮 626.9 秒、改 T8 代码连错三次，换成 Locals 后直接 4 轮 270.7 秒反超 Qwen3.8 接近一倍；可偏偏在同一套模型底座上遇到重度对抗逻辑 T5，它却连吃两轮 28,672 思考上限直接 25 分钟超时翻车。

　　这次测试之后，我也顺手把 Locals 引擎遇 DeepSeek Harness 大工具集报 DFA exceeds 400000 states 的问题，以及外部模型扫描混入过渡/底座目录的小毛病一并修掉，打包推出了最新的 方寸智匣 Mac 2.4.5 发行页。今天就把这 三版本全量数据、文字回答真实含金量、核心原理与清晰选型边界 一次摆清。

三、拆开看机理：同底座换引擎，为什么性能差距这么大？

　　同样一具 Inkling-2-Mini 权重，换成 Locals 以后从“慢且漏参数”变成“快准狠”的同时又丢掉了 T5 稳定性，原因全在下面几处底层机理：

　　第一刀：48 层循环骨相撞上 6 颗融合 Metal 核。 Thinking Machines 这套 Inkling-2-Mini 总参数 26.4B，物理却只放了 24 层，第 6 到第 17 层在原地循环滚 3 遍，单 token 等效 48 层逻辑深度。普通 Python/MLX 跑起来每步切出约 6,000 个零碎调度操作（相邻读写之间夹着上百个小算子），GPU 光等 CPU 发令了；而 Locals 用 mix / kv_prep / attend / route / act / combine 6 个融合 Metal 核把整条链路焊成一个整块，大幅抹掉了调度空窗。

　　第二刀：0.64 GB 草稿在写代码时开挂，在纯中文长考时回到基线。 这点我自己接入外部 DeepSeek Harness 实测也能直接印证：日常普通中文问答只有 38–42 tok/s，并不像网帖截成 85 tok/s 那么神（那个数其实是同时开 8 个子代理的 8 路合算总吞吐）；真正的单路暴走发生在写 HTML / 局部改代码时——代码语法极好猜，Locals 的 0.64 GB 草稿命中率冲到 76%–94%（T2 3,832/5,043 飙出 60 tok/s、T8 改文件 83.9% 命中、T1 792/843），效率才猛跳一大截。

　　第三刀：llguidance GPU 语法锁治好漏参数，但碰到 40+ 工具需要大工具集自动退化。 在 Locals 上开 --walk --typed-tools 会把工具 JSON Schema 编成字节自动机压进 Metal 掩码里（T8 和 T7 之所以 0 报错一发过关靠的就是它）。不过我们实测一接入 DeepSeek Harness 这类自带 40+ 工具和海量可选参数的宿主，原本为每个字段枚举类型的强语法瞬间会胀破 40 万 DFA 状态报错 400 DFA exceeds 400000 states。刚发布的 方寸智匣 Mac 2.4.5 已经加了智能降级守卫：紧凑工具集继续锁死参数类型拿加速，一旦工具表过大自动平滑切回非强类型工具文法（DFA 状态瞬间压回 ~950 个），45 工具实测直接流式跑通。

　　第四刀：NVFP4 + 方向 LoRA 循环放大的微扰代价，以及前缀缓存的红利。 在本来每步就循环 3 遍的稀疏架构上先压 NVFP4、再叠去对齐方向 LoRA，遇到 T5 这种走错一步全盘坍塌的高难度组合反证题，微小的分布偏移被放大后让模型在 <think> 框里反复推翻自己直至超时。另一方面，前缀缓存的威力极大：看下方右侧那组实测——同样三万多 token，Locals 冷预填要 69.5 秒，二轮同前缀追加提问瞬间命中 32,893 / 32,995（99.7%），首字 TTFT 直接跌到 0.92 秒；而只要第 0 个 token（比如系统提示开头放时间戳）变了 1 个字，整棵缓存树当场作废回到 73.25 秒。

四、三版本各自优势与客观评价：到底该留哪一个？

　　把测试账算到底，其实三套方案在本地工作流里各有站位，谁都不用急着“一刀全删”：

  1. Qwen3.8-27B 越狱版（Splash + DFlash2）—— 大内存工作站的全能主力（最稳）：逻辑最强（T5 唯一满分 3/3）、视觉 OCR 最准（T9 零错字、T4 快 4.86 倍）、256K 长文解码最快（76.32 tok/s）。缺点只一条：吃内存、门槛高（32GB–64GB+ 且依赖新 macOS Metal）。只要机器内存够大、想找一个写作+读图+重推理+复杂工程全扛得住的主力，依然首选它。
  2. Inkling-2-Mini-Locals（Locals NVFP4 + 草稿）—— 24GB 机器与并发工具流的速度尖兵（最划算）：6 项日常工程/写作/检索总耗时 856.7s 最快（T7 4 轮 270.7s、T8 零错 63.8s、T6 62.0s），约 16.2 GB 体积能塞进 24GB Mac，原生支持 16 槽连续批处理适配外部 DeepSeek Harness / OpenCode 多子代理并发。明确短板：不能看图、30K 冷预填较慢（69.5s）、不能拿去死磕极高难度纯数学/逻辑证明。
  3. Inkling-2-Mini 原版（oMLX 0.8.2）—— 轻量级“保留看图 + 稳定收口”专职备选：在纯文本赛道它已经全面被同门 Locals 取代，但它是这套 16 GB 级权重里唯一完整保留 inkling2_vision 视觉编码器、且长思考不会像 Locals 那样爆满超时死循环的版本。在 方寸智匣 2.4.5 里，“Locals 跑纯文本/多工具并发 + oMLX 留作看图读屏专口”刚好互补共存（新版外部模型扫描也已经自动藏掉 _src-* 过渡目录、零碎组件与软链底座，主页只保留唯一干净入口）。

引用：实测落底 把融合 Metal 核、投机草稿与 GPU 语法锁焊在一起的 Locals，确实让一款 24GB Mac 可跑的小模型在代码工具与日常写作耗时上反手赢过 27B 稠密大模型将近一半；但在需要稳健长逻辑收束和高清细节读屏时，Qwen3.8-27B + DFlash2 依然是大内存主机上的定海神针，而“日常编码用 Locals、看图切 oMLX、大内存上 Qwen3.8”才是当下最省心的组合。
