After finishing an article or a commentary, the most time-consuming part is often not writing, but turning it into a video that can be sent: finding the frame, adding narration, adjusting the timeline, exporting. Tencent's newly launched tencent/WeVisCut on Hugging Face aims to take on this task—it's not a text-to-video model, but a 9B tool-calling agent that reads the current editing status and selects one of 12 tools to use.

The official model page clearly states its positioning: turning knowledge articles or commentary scripts into multi-minute finished videos. Each step involves planning, narration, retrieval, compositing, checking, or fixing. These 12 tools are like rows of buttons on the editing console, with the model playing the role of the person sitting in front of the desk, knowing which press next.

![Official Model Page Summary](https://hyphentech.top/obsidian-assets/2026-10-30-official-0c09b8d1f7f7/source-evidence-1-279ac575.png)

> It is not a standalone text-to-video model; use it with the WeVisCut runtime, which executes the model's tool calls.

This is a key point to understand before using it: downloading model weights alone doesn't directly produce a video; it requires the WeVisCut runtime to actually execute the tool calls it sends. In everyday terms, it's like buying a chef who can write recipes, but the stove and stove he needs for cooking must be provided by another kitchen system. Weights are the "brain"; the runtime is the kitchen.

![](https://hyphentech.top/obsidian-assets/2026-10-30-official-0c09b8d1f7f7/meme-d9383468fb6c.jpg)

## Where is the weight, who is the pedestal?

The model page specifies the model scale as 9B parameters, tensor type BF16, uses Safetensors format, and the model tree shows its base as Qwen/Qwen3.5-9B-Base, which is fine-tuning based on Qwen3.5-9B. The official description states that its strategy is based on Qwen3.5-9B and trained on executable clip trajectories. In other words, its "clipping intuition" comes from sequences of actions it has seen, rather than guessing on the spot during reasoning.

The licensing section is divided into two parts and must be viewed separately: code is released under the Apache License 2.0; Model weights and third-party components each follow their respective license terms. This division is crucial in practice—the code part can be flexibly modified, but whether weights can be used commercially or redistributed must be determined separately according to the permission of the weight repository, not directly applied from the lenient code.

## What does it take to run locally?

![Official Deployment Requirements](https://hyphentech.top/obsidian-assets/2026-10-30-official-0c09b8d1f7f7/source-evidence-2-1280dc54.png)

The official deployment requirements are: Python 3.11 or later, an NVIDIA GPU with about 24GB of VRAM for bf16 inference, and PyTorch matching the local CUDA version must be installed first. The installation script will also include Node.js, FFmpeg, and renderer. The overall process is cloning the repository, installing requirements and requirements-gpu, running setup scripts, then using huggingface_hub to download tencent/WeVisCut to checkpoints/weviscut-9b, finally launching bash run_studio.sh and opening port 8081 into Studio.

```bash
git clone https://github.com/Tencent/WeVisCut.git
cd WeVisCut
pip install -r requirements.txt
pip install -r requirements-gpu.txt
bash scripts/setup_external_tools.sh
pip install -U "huggingface_hub[cli]"
hf download tencent/WeVisCut --local-dir checkpoints/weviscut-9b
bash run_studio.sh
```

If you just want to see what the interface looks like first, the official has a lightweight entry point: bash run_studio.sh --no-model, which runs Studio without loading any model weights. This is friendly for those who want to judge whether the editing process suits their taste, as you don't need to free up a 24GB graphics card first.

## What kind of experience is it actually delivering?

![Official Finished Film Quality Description](https://hyphentech.top/obsidian-assets/2026-10-30-official-0c09b8d1f7f7/source-evidence-4-4ea8a8cd.png)

The runtime's capabilities are described as: providing an editable timeline, supporting pause and continuation, manual and conversational editing, per-shot rerendering, and version rollback. These factors determine whether the device can be included in daily workflows—you can stop and manually modify a version, or revert to the previous version if it breaks, rather than just running it over and waiting for the result.

The official team also explicitly acknowledges that the quality of the finished product depends on external configurations: search services, TTS services, rendering services, and available templates. In other words, when it comes to "turning a draft into a video," the model decides how to edit and where to add it, while where the material comes from, how the sound is read, and how the final image is composited, all depend on the services you accept. If the service isn't done well, no matter how smart the model is, it won't produce the final product.

![Official Custody Support Status](https://hyphentech.top/obsidian-assets/2026-10-30-official-0c09b8d1f7f7/source-evidence-6-355acd5a.png)

> [!warning]
> The official section "Intended Use and Restrictions" clearly states that it is intended for research and production assistance in long-form video editing, does not guarantee factual accuracy or production quality, and requires manual review of generated narration and videos before release. This restriction is worth remembering—it is an assistant responsible for the work, not an automaton that can send messages without watching.

Additionally, the model page shows that no Inference Provider has deployed this model yet, and the page displays a "Request Provider Support" entry point. If you want to take the easy path of managed APIs, there are currently no ready-made options; building your own is the main path.

## When is it worth trying?

If your daily output is the kind of "draft already written, just short of cutting into a single strip," this project is worth considering: it breaks down editing actions into 12 callable steps, leaving room for pause, rollback, and per-shot rerendering. The accompanying paper is arXiv:2610.38352, titled "WeVisCut: The Whole Editing Room in One Agent From Narration to Long-Form Video," and the model page shows the paper was published two days ago.

If your graphics card doesn't reach 24GB of VRAM, or you prefer a ready-to-use online service, now isn't the right time to buy—the former is a hard barrier, and the latter currently has no available hosting providers. The easiest way to verify is to first run the --no-model mode to see if Studio timeline interactions are suitable, then decide whether to invest in a graphics card.

The model page also provides the project repository address. The code is under the Apache License 2.0, and weights and third-party components are executed under their respective licenses. Those who need to use or redistribute them should follow the license terms of the weight repository.
