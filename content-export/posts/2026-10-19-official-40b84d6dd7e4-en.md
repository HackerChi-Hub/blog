Tencent Hunyuan's official model list has added tencent/Hy-Memory-30B-A3B-GGUF, and three tiers of quantization files have been made public, with the smallest Q4_K_M only 18.24 GB. It's not a chat model, but a dedicated 'writer' for long-term memory frameworks: deciding which conversations are worth recording, what format to write, and how to update old memories. This article answers only one question—can you run it on your own machine now, and what it actually does for you once it starts?

## What is it: a model specifically designed for writing memories

Hy-Memory-30B-A3B is a compact long-term memory writing model developed by Tencent Hunyuan. According to the official statement, it directly replaces the general large models from Mem0, MemOS, and Hy-Memory frameworks, covering Chat, Working, and Coding scenarios. You can think of it as someone in a courier sorting center responsible for labeling: when a package (conversation) comes in, they decide which item to put on the long-term shelf, what to write on the waybill, and whether to tear off and reapply old ones. The total parameters are 30B, but each activation takes about 3B, meaning the sorting center is huge, with only one assembly line actually working.

Training is divided into two stages: first, Memory On-Policy distillation, where the model learns to write state chains by following the teacher's signals in the real-world framework configuration; Next, Attributed Memory Reinforcement Learning, scoring by memory block, and moving the selected memory library to the next window. The official statement says the trained model can be directly transferred to the unfamiliar EverMemOS framework.

## The smallest path to run locally

The official recommendation is to build it with the latest llama.cpp, and provide a startup command verified on the specified commit. Core parameters are 64K context, single slot, F16 KV cache, no-think mode:

```bash
llama-server \
  --model ./hy3a3b-memrl1009-step250-Q6_K-imat.gguf \
  --alias hy-memory-q6-k-imat \
  --host 127.0.0.1 \
  --port 8000 \
  --n-gpu-layers all \
  --flash-attn on \
  --ctx-size 65536 \
  --parallel 1 \
  --batch-size 2048 \
  --ubatch-size 512 \
  --cache-type-k f16 \
  --cache-type-v f16 \
  --temp 0.7 \
  --top-k 0 \
  --top-p 1.0 \
  --repeat-penalty 1.0 \
  --jinja \
  --chat-template-kwargs '{"reasoning_effort":"no_think"}' \
  --check-tensors
```

If you want to open two concurrent slots, the official requirement is to set --ctx-size to 131072 to retain up to 64K context per request. After startup, you can call the request using the OpenAI Python SDK or directly curl the local 8000 port, explicitly adding reasoning_effort=no_think in the request for easier auditing.

## What can be done now, and what cannot be done yet

- You can now download three levels of GGUF from Hugging Face, follow official commands to start service llama.cpp, and connect Mem0, MemOS, or Hy-Memory as the write model.
- Official results show it averages higher than Claude Opus 5 and DeepSeek V4.1 Flash on fixed benchmarks, but these are official calibers and require you to retest them yourself on real data.
- Allowing download of weighted files doesn't necessarily mean your computer will run: Q4_K_M still needs 18.24 GB, and if you don't have enough video memory or memory, you'll need to downgrade or switch devices.
- It's not a universal chat model, so don't use it as a daily conversation assistant; Its value lies only in the long-term memory and writing pipeline.
- The next step is to run the memory write run using your own conversation data, check whether the memories are accurate and updated promptly, and then decide whether to replace the generic model in the existing framework.
