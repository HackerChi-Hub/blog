Tencent Hun Yuan's official model list adds tencent/Hy-Memory-30B-A3B-GGUF, and three tiers of quantized files have been released, with the smallest Q4_K_M only 18.24 GB. It's not a chat model, but a dedicated 'writer' for long-term memory frameworks: deciding which conversations are worth keeping, what formats to write, and how to update old memories. This article answers only one question—can you run it on your own machine now, and what it actually does for you once it starts?

## What is it: a model specifically designed for writing memories

Hy-Memory-30B-A3B is a compact long-term memory writing model developed by Tencent Hunyuan. According to official statements, it directly replaces the general large models in the Mem0, MemOS, and Hy-Memory frameworks, covering Chat, Working, and Coding scenarios. You can think of it as someone in a courier sorting center specifically responsible for labeling the label: when a package (conversation) enters, they decide which items go into the long-term shelf, what is written on the label, and whether to tear off or reattach old labels. The total parameter is 30B, but each activation takes about 3B, which is equivalent to a sorting center being very large, with only one assembly line actually doing the work.

Training is divided into two stages: first, Memory On-Policy Distillation, where the model learns to write state chains in the real framework configuration following the teacher's signals; Then Attributed Memory Reinforcement Learning, scoring by memory block and bringing the selected memory to the next window. The official statement says the trained model can be directly transferred to the unfamiliar EverMemOS framework.

## The minimum local running path

The official recommendation is to build it with the latest llama.cpp and provide startup commands verified on the specified commit. Core parameters include 64K context, single slot, F16 KV cache, and no-think mode:

```bash
llama-server \
  --model ./hy3a3b-memrl1009-step250-Q6_K-imat.gguf \
  --alias hy-memory-q6-k-imat \
  --host 127.0.0.1 \
  --port 8000 \
  --n-gpu-layers all \
  --flash-attn on \
  --ctx-size 65536 \
  --parallel 1 \
  --batch-size 2048 \
  --ubatch-size 512 \
  --cache-type-k f16 \
  --cache-type-v f16 \
  --temp 0.7 \
  --top-k 0 \
  --top-p 1.0 \
  --repeat-penalty 1.0 \
  --jinja \
  --chat-template-kwargs '{"reasoning_effort":"no_think"}' \
  --check-tensors
```

If you want to open two concurrency slots, the official requirement is to set --ctx-size to 131072 to reserve up to 64K context per request. After startup, you can call it using the OpenAI Python SDK or directly curl the local 8000 port, explicitly adding reasoning_effort=no_think in the request for easier auditing.

## What can be done now, and what cannot be done yet

- You can now download three GGUF files from Hugging Face, follow official commands and use llama.cpp to access Mem0, MemOS, or Hy-Memory as writing models.
- Official results show it scores higher on average on fixed benchmarks than Claude Opus 5 and DeepSeek V4.1 Flash, but this is the official caliber and requires you to retest it yourself on real data.
- Allowing downloads of weighted files doesn't guarantee your computer will run: Q4_K_M also needs 18.24 GB, and if memory or memory is insufficient, you will have to downgrade or switch devices.
- It is not a general chat model; do not treat it as a daily conversational assistant; Its value lies only in the pipeline of long-term memory writing.
- Next step for acceptance method: run memory writes using your own conversation data, check whether the memory is accurate and updated timely, then decide whether to replace the generic model in the existing framework.
