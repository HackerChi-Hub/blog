If your requirement is "to have video generation remember what happened earlier and be able to issue new commands while generating it," then the new repository opened by Tencent Hunyuan is worth paying attention to. Tencent Hunyuan officially added tencent/Hy-Nomas-Diffusers to Hugging Face, providing BF16 Diffusers format weights for Hy-Nomas. The model page shows 9B parameters, Apache-2.0 license, and the base model is tencent/Hy-Nomas.

![Official Announcement](https://hyphentech.top/obsidian-assets/2026-10-24-official-a3bd547a332b/source-evidence-1-3570d1cd.png)

Let's first clarify what it is. The official repository describes it as "a video model for free-form interactive world generation," supporting multi-turn interaction through text commands and camera control: it generates the world video by video, allowing users to introduce objects, change styles and scenes, describe actions, or control the camera during generation.

This is different from the common text-to-text videos where "a prompt can produce a few seconds of clip." More precisely, it is like a script that can be rewritten: the content generated from the previous segment is preserved as context, and the next segment continues downward instead of randomly drawing again. The official description of three key points for this capability is: freeform interaction, camera trajectory control, and continuous generation through KV caching and reuse of historical context.

![Project Process](https://hyphentech.top/obsidian-assets/2026-10-24-official-a3bd547a332b/source-evidence-2-7b96c70b.png)

### First, understand the two terms, then see if you can get the hang of it

![AI Mechanism Illustration](https://hyphentech.top/obsidian-assets/2026-10-24-official-a3bd547a332b/official-release-mechanism-landscape.png)

The "Diffusers format" can be understood as a way to break down a model into standard parts and package them—like dividing bulk parts into categories and labeling models according to the manual, so mainstream inference frameworks can load directly by directory without having to assemble them themselves. This warehouse contains these parts: the transformer directory is the distilled HyNomasTransformer3DModel, the decoder directory is the fine-tuned PixelUMMDecoder, the text_encoder directory is Qwen2_5_VLTextModel, the Qwen Segmenter file, the FlowMatchEulerDiscreteScheduler scheduler configuration, and a modular_model_index.json describing how each component is loaded. The official explanation states that these are serialized using HyNomasModularPipeline.save_pretrained().

"KV cache" is the space the model uses to remember things: during generation, the already calculated attention key values are left in memory, and the next segment is used directly without having to start from scratch. The advantage is that the context can continue, but the trade-off is that memory usage increases with the stored history—the official environment notes clearly state this: "Retaining history across segments increases KV cache memory use."

### The official operating conditions are given

The installation method is not the usual pip install diffusers, but rather from the source code branch: the official command is `pip install -e "diffusers[hy-nomas] @ git+https://github.com/jiaxiangc/diffusers.git@hy-nomas"`, and you need to upgrade diffusers before you can use HyNomasModularPipeline.

![Official Installation Instructions](https://hyphentech.top/obsidian-assets/2026-10-24-official-a3bd547a332b/source-evidence-4-27f4c250.png)

The sample code loads components onto a CUDA GPU using bfloat16 precision, outputs 704 × 1280, 24 FPS, with 4 steps of noise reduction per clip. Two 5-second clips are generated in the sample, totaling ten seconds. The official note also states: the example defaults to PyTorch's SDPA Attention. To closely match the native implementation, you need to install FlashAttention 2, FlashAttention 3, and MagiAttention as optional kernels—they are not automatically installed by hy-nomas as extra.

On the hardware side, the official does not provide a unified threshold, only stating that the example is loading BF16 components onto a single CUDA GPU, with actual memory usage depending on resolution, segment length, and cache history; Native deployment also includes an INT8/FP8 RTX 4090 configuration, which follows a different path. Generation speed also depends on hardware and inference settings, with no fixed commitment.

![Official Operation Instructions](https://hyphentech.top/obsidian-assets/2026-10-24-official-a3bd547a332b/source-evidence-3-66d31b19.png)

> [!warning]
> This Diffusers directory does not contain everything in the original model repository. Official note: Native checkpoints, quantization variants, adapters, and Nomas-PE assets are all kept in the original model repository and are not included in this Diffusers directory.

![Official Asset Description](https://hyphentech.top/obsidian-assets/2026-10-24-official-a3bd547a332b/source-evidence-5-073e0d56.png)

There's another common pitfall: the Nomas-PE used in web demos is an independent prompt enhancement service that converts user instructions into structured generated prompts; This Diffusers pipeline directly accepts plain text or pre-prepared structured prompts and does not call Nomas-PE itself.

### It can be used, but not as a toy

Based on currently available information, this repository is valuable for those who want to build their own interactive video workflows: open authority, clear permissions, complete component structure, and the official team provides multiple rounds of sample code that can be directly rewritable.

But its position is closer to a "research and development base" rather than a ready-to-use downloadable product. At least three gates must be passed through on its own: diffusers must be installed from the source code branch; optional attention kernels must be installed separately; video memory must simultaneously support the video branch, text encoder, decoder, and KV cache that grows with the number of dialogue cycles. The model page also notes that the model is currently not deployed by any inference service provider.

The company also released Hy-Nomas-Bench, a review set containing four benchmarks and 280 test cases, covering multi-turn freeform text interaction, camera navigation, control of text-to-camera interlacing, and spatial memory capabilities, with structured prompts, interaction sequences, keyboard timelines, and reference camera trajectories. These are official built-in evaluation materials that can be used to verify performance but cannot be considered independent third-party verification.

For the next step for acceptance, follow this order: first, confirm whether your GPU can run the official two 10-second generation segments on a single BF16 card, then check the VRAM growth curve of the KV cache after multiple rounds of dialogue, and finally compare the gap between yourself and the official camera path using the Hy-Nomas-Bench prompt and camera trajectory. These three steps better than any scoreboard show whether it suits your scenario.
