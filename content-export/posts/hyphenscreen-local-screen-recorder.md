先讲一件让我后背发凉的事。我给自己写的录屏软件做了自动打码——识别画面里的邮箱、密钥这些东西，盖上马赛克。功能做完，**单元测试全绿**：打码框的位置算得准，静止帧上看也严丝合缝。

然后我把成片导出来，从头到尾看了一遍。**画面放大的那几秒，马赛克没跟上，邮箱和一串 sk- 开头的密钥明明白白地露在屏幕上。**竖屏改版的裁切里也露了一次。单测测的是「打码框的坐标对不对」，而我真正要的是「成片里认不出敏感信息」——这两件事不是一回事，中间隔着放大、倾斜、裁剪和编码。

### 🛡 自动打码：本机识别，跟着画面走

![自动打码：密钥、邮箱和电话盖上马赛克，页面滚动时框跟着文字走](/obsidian-assets/hyphenscreen-local-screen-recorder/v101-zh-CN-redaction.jpg)

打码这件事真正麻烦的不是识别，是**跟随**。识别出邮箱只是第一步，接下来画面会放大、会倾斜、会被裁成竖屏、页面还会滚动——马赛克得跟着一起动，慢一帧就是一次泄露。

- 本机识别邮箱、手机号、证件号、银行卡号、密钥和你自定义的关键词（自动识别目前是 macOS），证件号和银行卡号先做校验，误报少。
- 打码跟随放大、倾斜、裁剪和竖屏改版。**页面滚动时，框一段一段跟着文字走**，只盖文字经过的那一小块——1.0.1 之前是一个框罩住文字经过的整条路，最坏能盖掉半个画面，这次顺手修了。
- 导出时如果你临时关掉了标注或缩放轨道，**打码轨道始终保留并提示你**——这条是故意不给关的。

### 🩺 成片体检：不信过程，只认成品

回到开头那个坑。教训是：**过程里的检查再绿，也不等于成品是对的。**所以导出完成后可以一键对成片本身做体检，检查项都落在「成品」上：

- **响度与真峰值**：给出输出音量建议，不用自己拿耳朵猜
- **无声段落和黑屏段落**：一段一段标出来
- **画面卡住**：成片停住了但原片还在动——这是导出出错最典型的样子
- **成片比时间线短**：片段超出素材长度，直接定位到素材用完的那一刻
- **字幕和标题放不下**：被裁掉或超出画面的都标出来
- **文字识别回读画面**：逐帧确认敏感信息没有露出（目前 macOS）

下面这组数字来自 0.4.13 安装版的一次实测回执（经软件自己的接口在验收工程上导出 1280×720/30fps 再体检，数字是程序写下的，不是我手抄的）：

| 体检项 | 实测结果 |
| --- | --- |
| 导出耗时 / 体检耗时 | 12.6 秒 / 34.8 秒 |
| 整体响度 · 真峰值 · 动态范围 | −18.2 LUFS · −2.8 dBFS · 3.7 LU |
| 文字识别回读 | 每秒一帧，共分析 150 帧 |
| 正常成片的结论 | 问题 0 项，提醒 0 项 |
| 故意去掉打码后重测 | 165.0–181.2 秒识别出邮箱与密钥，自动在 172.08 秒打上红色标记「体检：能读到邮箱 · 能读到密钥与密码」 |

> 回执文件 docs/evidence/export-check-0.4.13.json

> [!tip]
> **最后那一行才是重点。**一个检查器报告「没发现问题」，有两种可能：真没问题，或者检查器根本就没在干活。分不清这两者，它就一点用都没有。所以我每次都要拿一份**故意去掉打码**的成片喂给它——它必须把邮箱和密钥抓出来，抓到了，它在正常成片上说的「0 项问题」才值得信。

体检发现的问题可以一键标到时间线上，按 Shift+↓ 一个个跳过去改。

## 🧭 我的判断

如果你也做教程、评测、软件演示这类内容，录屏的真正成本从来不在录那十分钟，而在后面：删停顿、打码、转竖屏、检查有没有翻车。**这个软件的全部设计重心都在「录完之后」**，包括那道听起来有点笨的体检——导出完再看一遍成片。

笨办法有笨办法的好处：它不相信我自己写的任何一个中间步骤，只认最后那个文件。经历过「单测全绿但邮箱露出来」之后，我觉得这个不信任是值得的。这次给这篇文章拍截图，我又被自己的软件教育了一遍：**拍图的时候看出来三个问题**——切分片段会丢掉后面的音乐、滚动页面上的打码框太大、静音被转写成「[BLANK_AUDIO]」这样的英文标记——都是测试没抓到、画面一看就明白的。修好了才出 1.0.1。

> [!summary] 一句话收尾
> 黑粉录屏 1.0.1 是我自己在用的录屏 + 剪辑软件的第一个正式版：本机识别敏感信息并让马赛克跟着放大、裁切和滚动走，导出后回读成片本身做体检（响度、黑屏、卡帧、字幕越界，还用文字识别逐帧确认没漏），AI 用你自己的 Codex 订阅或本地模型在你的时间线上动手，录制和缓存放在哪自己定。免费下载，但还没签名、没公证，装的时候系统会拦一道。
