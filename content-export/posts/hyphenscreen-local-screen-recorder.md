先讲一件让我后背发凉的事。我给自己写的录屏软件做了自动打码——识别画面里的邮箱、密钥这些东西，盖上马赛克。功能做完，**单元测试全绿**：打码框的位置算得准，静止帧上看也严丝合缝。

然后我把成片导出来，从头到尾看了一遍。**画面放大的那几秒，马赛克没跟上，邮箱和一串 sk- 开头的密钥明明白白地露在屏幕上。**竖屏改版的裁切里也露了一次。单测测的是「打码框的坐标对不对」，而我真正要的是「成片里认不出敏感信息」——这两件事不是一回事，中间隔着放大、倾斜、裁剪和编码。

从那天起我给这个软件加了一道别的录屏工具基本没有的东西：**导出之后，回读成片本身做一次体检**，用文字识别一帧一帧看过去，确认该盖住的确实盖住了。这篇就讲这个软件现在做成了什么样。

顺便说说**录屏工具这门生意的钱从哪来**，这决定了它们把力气花在哪。常见的做法是：免费版给你加水印或者限时长，**把「导出」做成收费闸**；或者干脆做成云端服务，你把屏幕内容传上去，按存储和导出计费。屏幕录像是隐私浓度最高的一类素材——里面有你的邮箱、路径、token、没关掉的聊天窗口，**受益的是拿走这些素材做存储和转码生意的一方，代价落在传上去的人身上**。这套剧本在桌面软件里演过很多遍：买断版停更，功能一点点挪进订阅。

我做黑粉录屏图什么？说实话：**我自己每周要出片，录屏是主力素材，而我不想把屏幕内容交给任何服务器。**它没有订阅、没有云端、不卖存储，所以也没有靠你变现的路径；维护成本落在我自己身上。你据此可以判断：它不会为了赚你的钱变糟，但也可能因为我顾不上而停更。

## 🎥 录：先把「录什么」变简单

录制这一头没有太多可炫耀的，把常用的做顺手就行：整个屏幕、某个窗口，或者手动框选任意区域——**框选的时候单击一个窗口就直接取它的范围**，不用自己对边。需要固定比例时可以锁 16:9、9:16、1:1、4:3，录竖屏内容不用事后再裁。摄像头和麦克风同步录，光标高亮和「录制后自动缩放」默认开着。

![录制页：来源、系统音频、麦克风、摄像头、光标高亮、录制后自动缩放。自动缩放是按鼠标活动范围算的，不是固定倍数](/obsidian-assets/hyphenscreen-local-screen-recorder/image-record-35e50e9aff.png)

当年的录屏软件基本只管「录」，剪要另开一个软件，导出一次、导入一次，画质掉两道。所以这个软件从一开始就是录 + 剪一体，录完直接进时间线，中间不落一次编码。

## 🛡 自动打码：本机识别，跟着画面走

打码这件事真正麻烦的不是识别，是**跟随**。识别出邮箱只是第一步，接下来画面会放大、会倾斜、会被裁成竖屏——马赛克得跟着一起动，慢一帧就是一次泄露。黑粉录屏在本机识别邮箱、手机号、证件号、银行卡号、密钥和你自定义的关键词，打码跟随放大、倾斜、裁剪和竖屏改版；导出时如果你临时关掉了标注或缩放轨道，**打码轨道始终保留并提示你**——这条是故意不给关的。

## 🩺 成片体检：不信过程，只认成品

回到开头那个坑。教训是：**过程里的检查再绿，也不等于成品是对的。**所以导出完成后可以一键对成片本身做体检，检查项都落在「成品」上：

- **响度与真峰值**：给出输出音量建议，不用自己拿耳朵猜
- **无声段落和黑屏段落**：一段一段标出来
- **画面卡住**：成片停住了但原片还在动——这是导出出错最典型的样子
- **成片比时间线短**：片段超出素材长度，直接定位到素材用完的那一刻
- **字幕和标题放不下**：被裁掉或超出画面的都标出来
- **文字识别回读画面**：逐帧确认敏感信息没有露出

下面这组数字来自 0.4.13 安装版的一次实测回执（经软件自己的接口在验收工程上导出 1280×720/30fps 再体检，数字是程序写下的，不是我手抄的）：

| 体检项 | 实测结果 |
| --- | --- |
| 导出耗时 / 体检耗时 | 12.6 秒 / 34.8 秒 |
| 整体响度 · 真峰值 · 动态范围 | −18.2 LUFS · −2.8 dBFS · 3.7 LU |
| 文字识别回读 | 每秒一帧，共分析 150 帧 |
| 正常成片的结论 | 问题 0 项，提醒 0 项 |
| 故意去掉打码后重测 | 165.0–181.2 秒识别出邮箱与密钥，自动在 172.08 秒打上红色标记「体检：能读到邮箱 · 能读到密钥与密码」 |

> 回执文件 docs/evidence/export-check-0.4.13.json

> [!tip]
> **最后那一行才是重点。**一个检查器报告「没发现问题」，有两种可能：真没问题，或者检查器根本就没在干活。分不清这两者，它就一点用都没有。所以我每次都要拿一份**故意去掉打码**的成片喂给它——它必须把邮箱和密钥抓出来，抓到了，它在正常成片上说的「0 项问题」才值得信。

体检发现的问题可以一键标到时间线上，按 Shift+↓ 一个个跳过去改；这些标记还能直接复制成视频简介里的章节时间码。

AI 这块我的选择是**不捆绑**：不内置模型、不代收 API 费用、不替你决定用谁。你已经登录了 Codex 订阅就直接复用（不用填密钥），想全本地就接方寸智匣 LocalBrain。目前 54 个工具覆盖剪辑、声音、字幕、转场、打码、放大、标记点、逐片段特效、竖屏改版、导出和体检，外加 12 个一键模板——比如「压缩停顿」「去除口头禅」「删除重复与重录」「发布前体检」。外部 AI 也能通过 MCP 接口调用同一套工具（加上读取、保存、撤销、重做共 58 个）。

上一次我对「AI 剪辑」心动是那波一键成片，演示惊艳，真放进出片流程就留不下来——因为它替你做完，而你只能全盘接受或者推倒重来。所以这里的 AI 是**在你的时间线上动手**，每一步都落成可撤销的编辑，你随时能接管。

## 📤 出片：竖屏、断句和导出

![导出面板：格式、帧率、编码格式。导出完成后可以直接对成片跑体检](/obsidian-assets/hyphenscreen-local-screen-recorder/image-export-b7a9e2cfca.png)

两个细节是我自己被烦到才做的。**一个是竖屏精彩片段**：把横屏录屏的一段转成 9:16，软件操作的画面按鼠标位置裁切，网页和文档则整幅保留、标题在上字幕在下，放大只在画面区域内进行。**另一个是中文断行**：字幕和标题按中文词语换行，不会把「先跑」「哪个」从中间切开，数字和英文型号不拆，预览和导出断在同一处。

## ⚠️ 它现在的限制

- **预览版，不是稳定版**：版本号还在 0.4.x，功能和界面都还在动，只保留当前一版。
- **都没有正经签名**：Mac 版用我自己的证书签名、未做苹果公证；Windows 未做代码签名，首次运行会弹 SmartScreen；Linux 也未签名。
- **Windows/Linux 缺三项功能**：人声隔离、自动打码里的敏感信息识别、框选时「单击窗口取范围」——它们依赖只做了 macOS 版的本机组件，界面上会直接提示。
- **Linux 依赖多**：录屏全部经 xdg-desktop-portal，还要 Vulkan 驱动和对应桌面的 portal 后端。

顺带说个我自己的规矩：这篇文末那份自制软件名单是程序按名录生成的，**只印已经能公开下载的东西**——黑粉录屏今天才刚公开，等这篇文章上线，它才会正式进那份名单。名单里没有的，就是还不能下的。

## 🧭 我的判断

如果你也做教程、评测、软件演示这类内容，录屏的真正成本从来不在录那十分钟，而在后面：删停顿、打码、转竖屏、检查有没有翻车。**这个软件的全部设计重心都在「录完之后」**，包括那道听起来有点笨的体检——导出完再看一遍成片。

笨办法有笨办法的好处：它不相信我自己写的任何一个中间步骤，只认最后那个文件。经历过「单测全绿但邮箱露出来」之后，我觉得这个不信任是值得的。
