# LocalBrain 网络安全测试：关进隔离沙箱，默认跑不起来，授权了才放行

这两天我给 LocalBrain 加了一个我自己都犹豫要不要做的功能：对授权目标做主动网络测试。先把结论放前面——它默认是**跑不起来**的，而且我花在「让它跑不起来」上的功夫，比花在「让它能跑」上的多得多。

一个本地 AI 工具箱，为什么要碰网络测试这种听起来就危险的东西？因为我自己有需要：手上有几台自己的机器和服务，想顺手确认某个端口开没开、某个服务回的响应头对不对。但只要这类能力一旦接进一个能被对话驱动的工具里，第一反应就该是警惕——万一模型自己发起呢？万一指到了不该指的地址呢？万一它顺着网络摸到我本机的别的东西呢？这篇就讲我怎么把这三个「万一」一个个堵死。

## 先说它到底能做什么，不能做什么

**授权网络检查**能做的，只有两类低影响检查：连接检查（某个 IP 的某个端口通不通）和 HTTP 响应头检查（拿回响应头看看）。就这两样。不是全功能扫描器，不扫端口段，不发攻击载荷。响应头检查目前使用明文 HTTP，不能把它当成已经支持 HTTPS 证书或 TLS 配置审计。

能测的目标也被卡得很死：**必须是单个明确的 IP**——不接受域名、不接受网段、不接受通配符，连 IPv4 映射地址这种绕过写法都拒掉；一次最多 8 个端口；有效期 1 到 60 分钟；最多同时挂 8 条授权；而且全部只存在内存里，**退出应用就没了**。要测本机或内网，还得单独勾一个授权,不勾就连 127.0.0.1 都指不了。

这些限制不是建议，是代码里的硬门槛，填错直接拒绝。

## 第一个「万一」：模型会不会自己发起？

不会。这一条是地基。

授权网络检查的所有操作——建授权、跑验证、运行测试——全是设置界面里你自己点的按钮，一个都没注册成模型可以调用的工具。模型在对话里说「我帮你测一下」，也不能因此执行网络检查。简化后的流程仍要求亲手勾选目标授权，再点「授权并运行检查」；自动填表不等于自动授予权限。

把「能不能测」从「工具愿不愿意」挪成「人授没授权」，这是我做任何危险能力时的第一条线。

## 第二个「万一」：会不会指到不该指的地方、摸到本机别的东西？

这是最花功夫的一块，我换了两种思路才做对。

测试得在一个隔离环境里跑,我选了 Colima 加 Docker——起一台最小的专用 Linux 虚拟机（2 核 2G,`--mount none` 不挂我任何一个本机目录），LocalBrain 只用这台专用实例,不碰你机器上别的 docker。

一开始我想得挺自然:让测试容器能上网,然后用防火墙规则「只放行授权的那个 IP 和端口,其余全丢」。结果在 Docker 29 上翻了车——它把内部的 iptables 链整个重写了,我加的放行规则命中计数是 0,连授权端口都连不上。靠和 docker 抢防火墙链,既不可靠又会随它版本变动而失效。

后来我换了个根本思路:**不做「允许大部分、禁止一部分」,而是「默认什么都到不了,只开一条缝」。** 每个测试任务起一张 docker 的 `--internal` 网络——这种网络里的容器,我实测过,连默认路由都没有,跨网、公网全部连不上(nc 探测一律超时失败)。出口为零不是我用规则堵出来的,是 docker 的构造保证。

那它怎么还能测到授权目标?唯一的那条缝,是每个任务配一个只会往授权目标转发的小代理。测试容器只连得到这个代理,而且**它自始至终不知道真实目标的 IP 是什么**——它只往代理打,代理只往授权地址转。代理和测试跑在两个不同的容器里:测试容器能跑探测但哪儿都去不了,代理有出口但只会拨那一个地址。两个容器都丢光权限、只读文件系统、非 root 运行、限死内存和进程数、不挂任何本机目录。

这套设计把探测流量限制在每次任务的代理路径上，但不能据此承诺绝对安全：容器、虚拟机和代理自身仍属于需要维护的安全依赖，五项靶场检查也不能替代完整安全审计。

## 第三个「万一」:我怎么知道这套隔离是真成立,不是我以为成立?

这是我最在意的一点。安全功能最怕的就是「看起来关着,其实有缝」。所以我没让它默认能跑,而是加了一道**本地靶场反向验证**:点一下,程序自己起一个一次性的靶场,然后用真实的测试链路去撞五件事——

1. 授权的目标,能不能经代理正常测到?(要能)
2. 同一个目标上没授权的端口,拦不拦?(要拦)
3. 绕过代理直接连目标,有没有路?(要没有)
4. 连公网,通不通?(要不通)
5. 点停止,任务的容器和网络拆不拆得干净?(要拆得干净)

五件事**全过**,程序才会写下一条验证记录,执行才被放开。我这台机器上实测跑完整套大概 4 秒多,五项全过。只要隔离环境离线、或者镜像缺了、或者没有这条验证记录,执行就自动回到禁用——我管这个叫 fail-closed:**出了任何岔子,它倒向「关」,不倒向「开」**。

验证完我顺手停掉了隔离虚拟机,面板立刻就显示「隔离环境离线 · 执行已禁用」了,这就是我要的效果:隔离一走,能力自动落锁。

## 界面：按具体功能命名，用户选方案，不再记阶段编号

功能做完,界面我按「一看名字就知道干什么」来收:设置的系统访问里只留一个「网络安全」板块,里面两个选项卡,按功能命名——

- **工作区安全审查**：读取授权工作区的代码、依赖和配置。执行本地测试、依赖审计命令仍需另行确认；依赖审计可能访问软件仓库，不能笼统说成完全不联网。工作目录限制也不是系统沙箱。
- **授权网络检查**：对明确授权的 IP 和端口，在专用隔离环境里做连接与响应头检查。

名字直接说功能，不再叫「第几阶段」。已安装 Colima、Docker 和 Lima 依赖时，程序可以自动准备隔离环境、补齐镜像并执行本地反向验证。没装依赖的机器仍需要先完成一次安装，应用目前不会静默替你安装系统软件。下面的旧界面截图说明原有入口，不是本次修复版界面的验收截图。

## 一次真实故障：终端能启动，应用却找不到 Lima

这次不是模型回答错了，而是应用的启动环境出了问题。界面报的是：`limactl` 不在 `PATH` 中。程序已经找到了 Colima 的绝对路径，但 Colima 随后还要调用 Lima；从桌面启动的应用没有继承终端里的完整搜索路径，于是第二层依赖找不到。

我用只有系统目录的精简环境重新启动专用实例，复现了同一条错误。再把本机实际存在的工具目录补进子进程环境，隔离虚拟机成功启动，约用 8 秒。这个时间是在本机已有依赖与镜像缓存的条件下测得，不是新机器首次安装耗时。

修复没有往用户的 shell 配置里写东西，也没有要求把软件重新装一遍，而是从进程机制上处理：保留原搜索路径，再补齐存在的常用工具目录，让 Colima 及其子进程拿到一致的运行环境。同时补了另外三处可靠性问题：

- 启动日志持续读取，只限制保留长度，不停止读取。避免日志填满管道后，进程与应用互相等待。
- 耗时命令在后台线程执行，界面不必等隔离环境启动完才能响应。
- 出错后的状态刷新不再清掉错误；专用实例启动显式禁止自动切换用户的默认 Docker 上下文。

这些修复不根据模型名称分支，也不靠修改模型提示词掩盖运行时故障。

## 本地靶场实测：能测到授权目标，也要证明测不到其他目标

2026 年 10 月 3 日，我在 Apple Silicon Mac 上通过真实 Colima 与 Docker 执行器重新测试。对象是测试程序创建的一次性本地靶场，没有拿公网网站做试验。

| 验证项目 | 预期 | 本次结果 |
| --- | --- | --- |
| 授权目标经代理访问 | 可达 | 通过 |
| 同目标未授权端口 | 被拒绝 | 通过 |
| 绕开代理直接连目标 | 不可达 | 通过 |
| 探测容器连接公网 | 不可达 | 通过 |
| 停止后拆除任务容器与网络 | 完成清理 | 通过 |

五项反向验证合计约 **4.43 秒**。另一个完整链路测试用了 **7.61 秒**，覆盖验证记录、创建授权、拒绝未确认执行、确认后的连接检查返回成功、撤销授权和清理靶场。测试结束恢复原有验证状态，不用测试顺手留下一个永远开放的执行开关。

这里的「通过」只说明本机这条链路和上述五项边界有效。它不代表已经做过渗透测试，也不代表 Windows、Linux 或每种虚拟化环境都通过了。

## 简化后的操作：三步就够，细节留在高级选项

修复版把日常操作收成三个步骤：

1. **准备环境**：点「一键准备检查环境」。自动启动专用实例、补齐镜像，再运行本地验证。已在线但缺镜像时也会补齐，不再直接跳过准备。
2. **选择方案**：网页服务预填 80 端口，开发服务预填 8080 端口，两者都选连接与响应头；SSH 服务预填 22 端口，只检查连接。也可以自定义。方案不会帮你填目标 IP，更不会扩大授权范围。
3. **确认授权并运行**：输入你有权检查的 IP，核对端口，勾选授权声明后点击按钮。检查类型、有效期和内网授权放在高级选项里，仍可手动调整。

环境状态和五项验证细节默认折叠，需要排查时再展开。端口输入如果混入非法内容，会直接拒绝，而不是悄悄删掉错误项后替用户执行。

**版本说明：以上流程与运行时修复已在开发代码及本地真实执行器中验证。现有 1.5.7 下载包并不自动等于包含本次修改；正式安装包更新及原生界面验收完成后，才可把它写成发行版能力。**

## 老实交代边界

- 这套隔离和反向验证,**目前只在我的 Mac 上实测通过**。Windows 和 Linux 的安装包里有同一个功能,但隔离没在那两端实测过——好在它同样是 fail-closed,那两端也得各自在本机跑过反向验证才会放开执行。
- 只有连接检查和响应头两类低影响检查,**不是扫描器**。
- Linux 版本本身还是预览支持。
- 隔离环境要你本机装 Docker/Colima,默认不随应用装。
- 测试结果是「工具发现」,没经你人工复核不等于「已验证的结论」——这行字我直接写在了运行输出下面。

做这个功能最大的体会是:给一个能被对话驱动的工具加危险能力,真正的工作量不在「实现功能」,而在「把它关进一个就算想作恶也没有路的盒子里,并且能证明这个盒子是真的」。能跑,只花了我一小部分精力;让它默认跑不起来、而且证明得了跑不起来,才是大头。
