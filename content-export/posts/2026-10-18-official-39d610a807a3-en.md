Tencent Hunyuan's Hy-Memory-30B-A3B-FP8 weights, configurations, and model cards have already appeared in the official model repository. It is a quantized version of Hy-Memory-30B-A3B's FP8, and the official optimization direction is very specific: improving efficiency when deploying with vLLMs. The model page does not specify a clear release date, so it can only confirm the current resource status and cannot treat the page discovery time as the official release date.

This is not a general model mainly responsible for accompanying conversations or directly answering questions. It undertakes the "writing" part of the external memory framework: determining which information is worth keeping, how to accurately express it, and how old memories should be updated after new evidence emerges.

![Official Model Introduction](https://hyphentech.top/obsidian-assets/2026-10-18-official-39d610a807a3/source-evidence-1-4bbbfbbb.png)

## It addresses not "how to respond," but "what to remember."

You can think of the external memory system as the shelves at a courier station. General large models handle immediate pickup needs, while memory writing models decide which packages should be stored, how labels to fill, whether duplicate packages are merged, and whether new documents can overwrite old records. A large shelf doesn't mean it's well organized; If you write the wrong label, no matter how fast you search later, you might pick up the wrong items.

The official introduction states that this model can replace the general-purpose large models in Mem0, MemOS, and Hy-Memory that were originally responsible for writing memory, covering chat, work, and programming scenarios. The official statement also states that it can be directly migrated to the EverMemOS framework, which was previously unseen during training. The "migration" here refers to experimental results in the official report and does not mean that any external system will naturally achieve the same performance after integration.

![Memory Write Model Positioning](https://hyphentech.top/obsidian-assets/2026-10-18-official-39d610a807a3/source-evidence-2-9ff975e4.png)

The model uses two training stages: first, Memory On-Policy Distillation, where students learn the state chain provided by the teacher; then Attributed Memory Reinforcement Learning, where fragment-level feedback is allocated based on the final memory base. Simply put, the first stage is like organizing packages according to the standard, and in the second stage, adjusting the organizing method based on whether it is easier to find the right package.

## The official results are worth watching, but first look at the testing criteria

The official review only replaces the memory writing model, fixing the framework version, prompt, retrieval configuration, response model, judge model, and other framework components. Each write model starts from a blank memory and uses the same test examples and scoring rules. This design attempts to focus differences on "who is writing the memory," avoiding mixing changes in the retriever or answer model into the results.

![Official Review Control Variable](https://hyphentech.top/obsidian-assets/2026-10-18-official-39d610a807a3/source-evidence-3-f852ef54.png)

The main evaluation matrix uses a fixed 20% subsample. The scores for each framework are averaged equally weighted by six indicators, and the total score is equally weighted across four frames. Here, the macro average can be understood as four report cards each bearing equal weight, preventing one framework from having more questions and automatically gaining greater influence.

| Officially listed memory writing models | Mem0 | Hy-Memory | MemOS | EverMemOS | Average score |
| --- | --- | --- | --- | --- | --- |
| Hy-Memory-30B-A3B | 54.02 | 60.55 | 50.51 | 56.89 | 55.49 |
| Claude Opus 5 | 53.43 | 60.53 | 50.50 | 54.04 | 54.62 |
| DeepSeek V4.1 Flash | 49.73 | 60.20 | 49.17 | 55.47 | 53.64 |

> All of the above are fixed 20% subsample results listed in Tencent Hunyuan's official report and are not independent retests.

![Official Cross-Frame Score](https://hyphentech.top/obsidian-assets/2026-10-18-official-39d610a807a3/source-evidence-4-01775422.png)

These figures show that, under the official fixed components, fixed subsamples, and equal weight scoring methods, the average score for Hy-Memory-30B-A3B is 55.49. They cannot independently prove long-term stability in different production environments, nor can they replace testing real business data, retrieval strategies, and answer models. Especially since EverMemOS is officially listed as an external training framework, it still belongs to the same official experimental system.

## Thirty billion parameters does not mean you use three billion parameters every time

The model page lists it as a 30 billion parameter model, and the official description also notes about 3 billion activation parameters. You can think of this as a large express warehouse: the warehouse has many shelves, but when processing a specific waybill, only a portion of the area related to the current task is mobilized. The total parameter describes the overall capacity, while the activation parameter describes the actual scale of work involved in one calculation; the two cannot be confused as the same number.

![](https://hyphentech.top/obsidian-assets/2026-10-18-official-39d610a807a3/meme-af56f53a58ab.jpg)

The official Quickstart deploys using the tested vLLM v0.31.0 and is called via an OpenAI-compatible interface. The sample task extracts clear user facts and preferences from conversations, requiring output of concise, independent memories and prohibiting inference or fabrication. This demonstrates the official intended call method but does not constitute proof that other runtimes, devices, or configurations are already compatible.

![Official deployment example](https://hyphentech.top/obsidian-assets/2026-10-18-official-39d610a807a3/source-evidence-5-0c37a814.png)

## Who deserves further verification? Whoever should not rush to download it first

- Developers who have already used Mem0, MemOS, or Hy-Memory and whose general large model write cost or memory quality are bottlenecks can consider this as a candidate.
- Teams that need to handle long-term chat preferences, work logs, or code repository memories can set up their own validation collections using the official fixed variable method.
- Users who only need a regular chat model will not automatically get better answers just because they switch to a memory writing model; it is responsible for the memory writing process.
- Users who want one-click access to the managed interface are currently not suitable to rely on it directly, as the official model page shows no Inference Provider deployment yet.

The next step is not just to replicate the official average score. A more practical acceptance sequence is: first confirm the license and weight files, then check the target runtime and hardware conditions, then fix the retriever, answer the model and scoring method, and use real data to observe what it writes, what is missing, and how old memories are updated. Official model and resource portal: [Hy-Memory-30B-A3B-FP8 model repository](https://huggingface.co/tencent/Hy-Memory-30B-A3B-FP8).
