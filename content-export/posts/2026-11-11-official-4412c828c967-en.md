Multiple proxies can be divided, code changes can be reviewed by branch, but archive sessions may also clean up the local working tree. DeepSeek Harness released v0.2.2-rc.2 on November 11, 2026, bringing collaboration features and default behaviors that need to be migrated. The official release page marks it as a pre-release, not a stable official release.

If an existing project has already adopted custom plugins, search services, or team collaboration, whether to upgrade depends mainly on whether the new features solve immediate problems and whether old configurations can be carried over. Simply wanting to increase the number of agents participating in tasks is not a valid reason to directly switch to the daily work environment.

## Collaboration is easier to see clearly, but delivery still requires item-by-item acceptance

The official announcement lists the changes: SubAgent supports both named and multi-level collaboration, AgentTeam can be activated by session and shares members and task panels. SubAgents can be understood as assistants who handle tasks with division of tasks. For example, arranging work in a WeChat group and clearly writing participants' names and tasks makes it easier to track who is responsible for what than just a string of chat records; Multi-level collaboration allows for further division of labor.

![Official Announcement | Collaboration Features](https://hyphentech.top/obsidian-assets/2026-11-11-official-4412c828c967/source-evidence-1-51338fd0.png)

This update also adjusted the way to view division of labor: task descriptions are displayed first, support for layered expansion, and allow retries if a read fails. For projects that need to review different tasks back and forth, these changes are expected to reduce the burden of the search process. However, the panel clearly solves the organization and review issues; whether a task is done correctly still depends on the actual file, execution results, and acceptance conditions. The announcement does not provide data on collaboration success rates or completion times.

Users who have already integrated with teams should pay attention to migration requirements: AgentTeam switches to a unified named sub-agent, and interrupt tools are disabled by default; Custom plugins and SDK integration need to be migrated, and processes sharing sessions need to be upgraded synchronously. The SDK is the development interface used by programs to integrate this tool. If an existing program relies on the old collaboration method, it should first verify whether members and tasks display correctly and whether existing sessions can be restored before integrating the official task.

![Official Announcement | Collaborative Migration](https://hyphentech.top/obsidian-assets/2026-11-11-official-4412c828c967/source-evidence-2-32bbc3dc.png)

## Review and changes are more centralized, but archiving may take away the work catalog

This time, Git Worktree supports reviewing changes by branch, commit, and file type, and directly handles GitHub reviews, synchronizes reviewed progress, and updates branches. Branches can be seen as different modification routes for the same project: commits are version records saved along the way, and working trees act as workbenches set up for a particular route. Filtering by route, record, and file type during review makes it easier to identify the inspection targets than mixing all changes together.

![Official Announcement | Code Review](https://hyphentech.top/obsidian-assets/2026-11-11-official-4412c828c967/source-evidence-3-12465bfb.png)

Fixes directly related to review are also worth noting: the official team said they fixed the issue of review discrepancies and line numbers inconsistent with submissions after PR updates, and improved statistics on many review discussions. PR is a set of changes submitted to project maintainers for review; If the comment position after updating does not match the code version, the discussion easily loses its focus. For users who rely on this review process, this affects actual usage more than whether the interface looks better.

> [!warning]
> By default, archive sessions clean up the Git working tree that meets the criteria, keeping branches and commits; If you need to keep local directories, you should turn off cleanup. Custom configurations and Forge plugins need to be migrated.

![Official Announcement | Archive Cleanup](https://hyphentech.top/obsidian-assets/2026-11-11-official-4412c828c967/source-evidence-4-656293f5.png)

Keeping version records and keeping the entire working directory are two different things. This official statement does not promise to retain all contents in the directory, nor does it specify "eligibility" here. For projects that rely on local directories to continue working, you should first confirm the cleanup settings and back up the files that need to be retained; Do not directly interpret "archiving" as sealing as is.

## Before upgrading, check the search configuration and tool permissions

Web search defaults to the DeepSeek Search API, and you can choose either the billing account or API Key for searching and retrieving content. An API Key can be understood as a service call credential, like the proof shown when picking up a package, used to confirm which account service is being used for this request. This involves billing choices and cannot be directly inferred from the availability of features to be free; The announcement does not specify prices or bonus amounts. The old provider and custom configurations need to be adjusted according to the upgrade guide, but this announcement does not go into specific migration steps.

![Official Announcement | Search Configurations](https://hyphentech.top/obsidian-assets/2026-11-11-official-4412c828c967/source-evidence-5-70348357.png)

Tool permissions also can't just look at the status of "Sandbox Open." A sandbox is like a fence that limits the workspace; the key is which operations actually run inside the fence. The official explanation clearly states that Office document parsing runs in the main DSH process and is not protected by the command-line sandbox; Windows additional directory authorization is only for the file tool and does not extend access to the terminal or PTC. Being able to open files does not mean command execution has the same permissions.

![Official Announcement | Document Explanation](https://hyphentech.top/obsidian-assets/2026-11-11-official-4412c828c967/source-evidence-6-0d09eb9d.png)

Collaborative sharing also offers a more direct reminder: the old LiveShare license needs to be reconfigured, and PTC can access the sharing directory outside of the official directory. The official requirement is to share only with trusted individuals. Additionally, content from user terminals that are allowed to be read will enter the model and session records. If sensitive content such as credentials or customer data may appear in the work directory or terminal, the shared audience and readable content should be included in the upgrade check, not just whether the buttons are functioning properly.

![Official Announcement | Sharing Authorization](https://hyphentech.top/obsidian-assets/2026-11-11-official-4412c828c967/source-evidence-7-197d0995.png)

- Team collaboration is required: verify members' behavior after synchronizing and upgrading with task panels, session recovery, and shared session processes.
- Code review required: verify branch filtering, updated comment locations, and review progress, and confirm archive cleanup settings.
- Custom integrations already exist: check search providers, billing credentials, plugins, and SDK migrations, then confirm what files, terminals, and sharing licenses each cover.
- For daily stable use: remember this is still a pre-release version; Switching new update channels on desktop does not mean this version is stable.

For specific changes, please refer to [DeepSeek Harness v0.2.2-rc.2 official release notes](https://github.com/deepseek-ai/deepseek-harness/releases/tag/dsh-v0.2.2-rc.2). The attachment area on the release page was not successfully loaded in the existing materials, making it impossible to verify the installation package name, platform coverage, or download availability based on this; The existing working environment should not be replaced based solely on the announcement.

This upgrade is more suitable for users with clear collaboration or review needs and willing to handle configuration migration. What is worth testing next is not how many assistants can be arranged simultaneously, but whether tasks can be clearly reviewed, changes reviewed, and whether necessary files remain after archiving. If these steps cannot be connected, adding division of labor may only leave the organization work until last.
