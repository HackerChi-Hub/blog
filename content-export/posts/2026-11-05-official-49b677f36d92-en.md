Want to know which internal features are activated when Qianwen processes a sentence? ByteDance Seed's Cross-Layer-TopK-CLT provides a research entry point: extracting internal features from the Qwen3-8B-Base and using these features to reconstruct part of the internal computational results. Those who want to study the model's internal computation can continue reading; For those who want to directly improve chat performance, this resource does not provide corresponding commitments.

## It extracts internal features, not ready-made thought explanations

Officially, it is called a cross-layer transcoder, abbreviated as CLT. You can temporarily think of the internal processing process of the model as a sorting package: parcels pass through different stations, each station has information being processed. CLT reads this information from designated positions on each layer, converts it into a set of numbered features with activation values, and then reconstructs the output of the corresponding computing module using the selected features. Here, the numbering acts like a shelf location, telling you where the features are and how strong they are activated; The number itself does not include a pickup slip explaining its meaning.

For this project, the feature reading location is the residual stream before the MLP of each layer of the feedforward computing module, officially denoted as resid_mid; The reconstruction target is the MLP output, denoted as mlp_out. Features from each layer can participate in reconstructing the MLP output of the current and subsequent layers, so the observed relationships span layer to layer, not just within a single layer.

![Project Mechanism](https://hyphentech.top/obsidian-assets/2026-11-05-official-49b677f36d92/source-evidence-1-03144dbf.png)

The official structure is 36 layers, each containing 32,768 potential features. After encoding, the program scores the activation value and decoder column norms, jointly retaining the 360 highest scoring features across all layers. Here, Top K is cross-layer joint filtering, not each layer picking the same number of features.

This organizes internal calculations into records of sparse features for further analysis. However, the official examples show feature numbers, activation values, and the shapes of reconstruction results, without providing natural language meaning for each feature. To answer what a feature actually corresponds to, a separate verification process must be designed; the output list cannot be directly treated as a complete model explanation.

## Choose encoding or rebuilding first, then consider downloading

The most influential factor in usage choice is volume: the official CLT has 94.2 billion parameters, which is 94.2 billion parameters, uses fp32 format, and has a total file size of 377 GB. This is the scale of the transcoder itself, not a rewrite of the base model Qwen3-8B-Base to 94.2 billion parameters, nor is it a rating for chat capability.

If the goal is only to see which features are activated, you can choose to encode only. The official requirement is to set DECODE = False in the sample code and skip the decoder file; The documentation states that an 80 GB graphics card is sufficient to run this encoding example. For research tasks that do not need to reconstruct output for now, this path is more worth checking first.

![Coding Conditions](https://hyphentech.top/obsidian-assets/2026-11-05-official-49b677f36d92/source-evidence-2-e1fae2bb.png)

If you want to restore features to MLP output, you need a decoder. The official decoder file is 357 GB and provides a multi-card startup example using 8 processes. The file size stores information, and the startup command is a sample configuration; The document does not provide a universal minimum memory for complete reconstruction, nor does it list runtime and cannot be directly converted to a computer's available configuration.

The runtime should also be considered separately: the accompanying examples use PyTorch, CUDA, and NCCL. The documentation does not provide compatibility instructions for Mac, MLX, or other backend runs. Therefore, the weights are already open and existing computers can run directly on the computer, which needs to be confirmed separately.

## After the feature list appears, what should be inspected?

The official example uses preset sentences in the code, prints each word for activation features, and then reconstructs them into mlp_out. Word numbers can be understood as small segments cut into WeChat messages by the model: one fragment may not correspond to a complete Chinese character or word. The example lists features at different layers according to these fragments, so when reading output, you should look at the text fragment, its layer, and feature numbers together.

There are two settings that easily affect results during reproduction. The official explanation states that the activation normalization used for training has already been merged into the weight, so do not use the scaling factor in factors.safetensors; The base model should also use fp32 to match the activation accuracy during training. There is also outlier handling: when the correlation vector norm of any layer reaches 20 times the mean of that layer, the corresponding word is discarded, and the first word in the official example is marked as an outlier.

![Operating Precautions](https://hyphentech.top/obsidian-assets/2026-11-05-official-49b677f36d92/source-evidence-3-68012252.png)

Therefore, acceptance can proceed along the actual output: whether the code produces word-by-word and layer-by-layer feature records, whether outliers are handled according to rules, and whether the expected structure output is obtained after enabling reconstruction. To further judge the quality of the reconstruction, it is also necessary to compare the reconstruction value with the original MLP output of the base model. The page shows the shape of the reconstruction result but does not provide a reconstruction error score; The shape is successfully printed, but only the runway checks are completed.

## Who is it suitable for now, and where should we go next?

The official statement states that weights and code have been released under the Apache License 2.0; The licenses involved in training data are separately listed as ODC-BY. Before using or redistributing, the corresponding terms of the project and data should be reviewed separately. The page also shows that no inference service provider has deployed this model, so the warehouse entry cannot be treated as a ready-made online calling service.

If your need is daily chatting or you expect the tool to automatically explain the meaning of each feature, the current documentation does not provide such a usage process.

Next, you can check the [official project description and weighting entry](https://huggingface.co/ByteDance-Seed/Cross-Layer-TopK-CLT), focusing on reading [Example Runtime Instructions](https://huggingface.co/ByteDance-Seed/Cross-Layer-TopK-CLT#demo) and [File Format Instructions](https://huggingface.co/ByteDance-Seed/Cross-Layer-TopK-CLT#format).
