电脑上的 AI 正在改代码、跑构建，我人却不能一直坐在屏幕前。离开之后，它做到哪一步了？有没有报错？需要调整方向时，能不能掏出手机接着说？

这就是我这次给 DeepSeek Harness 加手机入口的起点。最近的方寸智匣构建任务已经交给本机的 Harness 接力，我想在外面也能看到同一项任务的执行结果，并继续发要求。

现在，**手机通过 HTTPS 网页已经能进入，并看到电脑上的原有会话**。独立的网页消息验收也完成了：发出要求，原来的模型返回“远程网页消息已收到。”任务仍由电脑上的程序处理，手机负责查看和操作。

![网页消息验收](/obsidian-assets/deepseek-harness-mobile-remote/image-web-message-74a6376fd4.jpg)

上图来自本轮独立网页验收，沿用了当时选中的 MiniMax 模型；界面记录这次简单回复用时 1 秒。它验证的是网页消息收发，**没有把这一秒算成复杂任务的执行速度，也没有当成手机端工具批准实测**。

## 手机接进来，为什么不用再开一轮对话？

我需要的是接着看电脑上的那项任务。另开一个手机聊天窗口，把前面的要求再解释一遍，很容易出现两边记录不同、文件状态不同的问题。

可以把它理解成：你在电脑微信里打开了一段聊天，手机端看到的仍是同一段记录。这里也是类似的操作关系——原会话保留在原来的 Host，也就是电脑上真正负责会话和工具执行的进程里，手机网页连回它。

![流程示意｜同一会话](/obsidian-assets/deepseek-harness-mobile-remote/image-same-task-1c400d9c1a.png)

因此，手机不会因为接入就获得电脑的算力，也不需要重新下载模型。电脑要保持开机，Harness 和网络入口也要正常运行。手机断开时，网关不会替你重新提交刚才的命令；任务是否继续、如何恢复，仍由原来的 Harness 管理。

这也意味着，DeepSeek Harness 这个名称不限定你必须使用某一个 DeepSeek 模型。此次网页验收沿用已有模型配置，新增的是接入和管理能力。

## 最折腾的地方，是页面明明能开却进不去

第一步把公网端口映射打通后，手机能够打开页面，但点击配对却提示配对码无效。后来服务器已经确认配对成功，手机仍显示“浏览器来源校验未通过”。单看页面能打开，很容易以为只剩刷新浏览器这一步。

实际情况是，**网络到达、用户配对、浏览器来源校验，是三件分别要过的事**。像快递进小区：地址写对能找到门口，取件码确认是谁来领，门禁再判断这次进入是否符合规则。网址通了，只证明找到了入口。

![过程重绘｜配对到进入](/obsidian-assets/deepseek-harness-mobile-remote/image-pairing-steps-4a232b92c4.png)

问题出在进入方式。手机从聊天软件里的链接或二维码进入浏览器时，首次页面导航可能被浏览器标记为“来自其他网站”。原先的检查把这种正常进入也挡住了。

修复时只放行了首页和登录页的顶层页面导航。真正读取任务、写入要求和建立实时连接的接口，仍按原来的来源约束检查。没有为了“终于能进了”，把所有跨站请求一并放开。

![回归记录｜页面与接口分开检查](/obsidian-assets/deepseek-harness-mobile-remote/image-source-check-47b487156a.png)

修复后的记录中，跨站进入首页返回 303，转到登录页；登录页返回 200；来自外站的写入请求仍返回 403，被拒绝。随后手机端确认：“已进入，能看到原有会话。”

我觉得这一步很有代表性。远程工具真正难的，往往不是把一个端口映射出去，而是让正常使用顺利通过，让不该通过的请求继续停在门外。

## HTTPS、配对码和登录凭据，各管什么？

HTTPS 负责保护手机到入口这一段通信，并让浏览器核对连接的是哪个服务。它像给快递加上封条并核对收件地址，但服务仍要判断来访的人是谁。**有证书，仍然需要登录认证。**

DeepSeek Harness 的官方部署说明也明确区分了这几件事：对外地址声明、允许的访问来源、登录凭据和加密传输，各自承担不同作用。已有部署可以按官方文档配置；我这次是在原有 Host 前面补了一层本人手机配对和管理。

- [查看 DeepSeek Harness 官方公共部署与 HTTPS 说明](https://github.com/deepseek-ai/deepseek-harness/blob/master/docs/user/guide/public-deployments.zh.md)

公众号中的这条外部地址会显示为文字，请复制到浏览器打开；Blog 版可以直接点击。

![流程示意｜私有访问](/obsidian-assets/deepseek-harness-mobile-remote/image-access-chain-12093a56a4.png)

具体到这套工具，本机生成的配对码十分钟有效，成功兑换一次就失效。手机浏览器拿到自己的登录凭据，放在浏览器管理的 Cookie 中；电脑原 Host 的凭据留在电脑上，不直接发给手机。

它有点像到前台用一次性取件码换一张临时通行证：取件码不能反复换证，通行证也只对指定入口有效。工具还给 Cookie 加了 HTTPS 专用、网页脚本不可直接读取等限制。

菜单中的“撤销登录”可以让所有手机重新配对，同时撤销尚未使用的配对码。生成新码只会替换未兑换的旧码，已经登录的浏览器不会因此被强行退出；重启网关则会让手机重新配对。

当前外网方案使用的是 **HTTPS 加本人配对认证**。它没有自动替你建立 VPN，也不会因为源码仓库私有，就让公网地址变成不可访问的内部网络。入口是否可达、谁能看见会话，仍要分别管理。

## 实时进度，不能打开十秒就断

只把网页正文转发出来还不够。任务输出、执行状态和后续操作，需要一条持续的双向连接。这里使用的是 WebSocket，可以把它理解为一直保持接通的电话：双方有新内容就直接传过去，不必每句话都重新拨号。

这轮保留并核对了一个细节：十秒超时只限制建立连接的握手阶段。连接成功后，要解除这个短超时，允许任务暂时没有新输出。否则页面刚打开，看着正常，安静一会儿通道就断了。

![回归记录｜空闲后继续收发](/obsidian-assets/deepseek-harness-mobile-remote/image-stream-check-ff78043a2a.png)

回归中实际建立了 HTTPS 下的双向连接，空闲超过旧的十秒门槛后继续交换数据，并核对断开后的清理。这个结果说明相关传输检查通过；手机切换移动网络与无线网络后的长任务恢复，仍需要专门验收。

## 从一次接通，整理成能长期管理的小工具

一次性脚本在自己电脑上跑通，离以后方便维护还有一段距离。我把这次实现另行整理为独立工具：中文菜单、单独的私有资料目录，以及 macOS、Windows、Linux 各自的启动入口。

0.1.0 便携压缩包大小为 **55,630 字节，约 55 KB**。这个数字只指工具源码压缩包：使用时需要已经安装 Node.js 22 或更高版本，也需要官方 Harness 和实际调用的模型环境。

![管理菜单｜运行记录排版](/obsidian-assets/deepseek-harness-mobile-remote/image-menu-82df1fd3db.png)

macOS 使用 manage.command，Windows 使用 manage.cmd，Linux 运行 sh manage.sh。菜单里可以挂载连接器、配置 HTTPS、启动后台服务、生成手机配对入口、诊断问题和撤销登录；退出菜单会保留后台服务运行。

连接器挂载只给原配置增加本工具的一段设置。移除时也只删除自己管理的区块，保留后来添加的用户配置；区块被改动或路径发生变化时会提示核对，不整份恢复旧文件。

![操作示意｜日常管理](/obsidian-assets/deepseek-harness-mobile-remote/image-management-b122f85f3a.png)

停止服务时也区分对象：工具先核对自己的控制通道，有手机登录时提示会断开并撤销登录。它不会仅凭发现一个进程号，就直接把 DeepSeek 或模型进程关掉。

外部入口有两种接法：已经有 HTTPS 反向代理或私有通道时，转发到本机回环网关；已有域名、证书和端口映射时，可以启用内置 HTTPS。回环地址可以理解为电脑内部的窗口，手机通过选定的外部入口来敲门，原 Host 不直接对公网开放。

DNS、路由器映射、防火墙和证书续期仍由已有环境明确配置，工具不会静默修改。需要更新证书时，可以校验并重新加载证书，保持原 Host 和任务运行。

## 目前怎么用，适合谁？

它适合已经在电脑上运行 Harness、希望离开桌面后仍能看同一项任务的人。手机可以减少来回守着电脑的次数，电脑的开机、网络、模型服务和原有批准流程仍要正常工作。

获授权使用这份工具时，顺序很简单：准备 Node.js → 打开本系统管理入口 → 挂载连接器 → 配置 HTTPS → 启动并诊断 → 生成配对链接 → 本人手机进入。已有任务正在执行时，先保留原入口，等空闲后再安排迁移。

这次工具的源码和下载包**保持私有**，只向本人及获授权协作者开放。本文公开介绍实现和验证结果，不提供面向所有人的脚本下载，也不公开我的真实域名入口、配对链接或证书。希望自行搭建的读者，可以先从上面的官方部署文档了解 Harness 的公开部署能力。

对我来说，这次最有价值的变化，是电脑继续执行原任务时，我可以用手机回到同一段工作过程。接下来值得补的也很具体：手机真实工具批准、切网重连、长任务恢复，以及 Windows 与 Linux 原生环境的验收。
