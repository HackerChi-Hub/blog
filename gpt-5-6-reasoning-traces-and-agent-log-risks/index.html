GPT-5.6 的“思考”真被偷走了吗？比标题更危险的是日志里的密钥

先给结论：这不是一次“攻进 OpenAI 或 Anthropic 服务器”的事件。现在流传的内容混合了两件不同的事：论文曾利用可重放的加密推理块提取隐藏记录；Oh My Pi 则让模型把新生成的工作草稿写进普通工具参数。前者已在负责披露后被厂商缓解，后者仍然存在，但它更像主动打开一条调试通道。真正需要警惕的，是这条通道会把秘密带进日志。

概念图：加密数据块进入外部工具与日志后，敏感信息的暴露面随之扩大。此图只解释风险，不代表任何厂商的真实系统界面。

“顶级模型的完整内部推理被导出了”，听起来像是有人撬开了模型机房。把论文、Oh My Pi 的发布记录和当前源码放在一起看，画面没那么戏剧化，却更值得开发者认真对待：模型没有被拿到 Root 权限，数据的安全边界却从模型内部，一路移动到了工具参数、会话文件、错误追踪和团队日志。

先分清两种“偷思考”

2026 年 8 月 10 日提交的论文《Stealing Reasoning Traces from Proprietary LLM APIs》，研究的是厂商 API 返回的加密推理块。OpenAI 的 Responses API、Anthropic 的 Thinking Block、Google 的 Thought Signature 都需要在多轮请求中保留一段不可读的数据，以便模型继续此前的推理状态。

研究人员发现，在当时的实现里，这些加密块可以跨会话、跨用户，甚至跨同一厂商的不同模型重放。他们把强模型生成的加密块交给防护较弱的同厂商模型，再通过特定提示要求后者转录。实验覆盖 Anthropic、OpenAI 和 Google。这里拿到的对象，确实指向此前请求留下的加密推理记录。

机制对比：上方是论文研究的历史加密块重放攻击，下方是 Oh My Pi 的外部草稿功能。 依据：论文项目页与 Oh My Pi 当前源码。

Oh My Pi 作者 Can 展示的 externalThinking 不是同一个机制。它先要求受支持的模型关闭原生推理，再向模型提供一个名为 think 的普通工具。这个工具只有一个字符串参数：thoughts。模型需要分析复杂问题时，就把工作草稿写进这个参数，然后继续回答或调用其他工具。

原始实验截图一：顶部显示 reasoning effort: off，随后 deep_think 的 thoughts 参数出现大段数论分析。图片引自用户提供 PDF，原始发布者为 Oh My Pi 作者 Can Bölük。

原始实验截图二：在原生推理关闭的条件下，Claude Fable 5 同样把逐步分析写进 think 工具参数。图片引自用户提供 PDF，原始发布者为 Can Bölük。

这两张图能直接证明：当原生推理被关闭、外部工具被提供后，模型仍会生成长篇分析，并把它作为普通工具参数返回给开发者。它们不能单独证明这些文字逐字等同于厂商原生隐藏思维链；更准确的说法，是外部工具记录了模型在新指令下生成的工作草稿。

简单说，论文尝试读取“上一张被加密的草稿纸”；Oh My Pi 是关掉原来的草稿纸，再递给模型一张开发者能保存的新纸。两者都能出现大量中间步骤，但证据含义不同。

这条区别很重要。一个模型在新提示下写出“我正在检查边界情况”，并不能证明它原本隐藏通道里逐字写的也是这句话。模型生成的解释可能忠实，也可能事后整理，甚至只是为了满足工具格式。能帮助排障，不等于拿到了 Transformer 的底层真相。

Oh My Pi 到底做了什么

Oh My Pi 是一个终端 AI 编程代理。核查时，它的 GitHub 仓库有 24,426 个 Star、2,328 个 Fork，贡献者列表约 435 人；仓库在 2026 年 8 月 13 日仍有代码推送。它不是临时拼出的概念验证，而是一套更新频繁的真实工具。

Oh My Pi 项目页，实时数字可能继续变化。 来源：GitHub 仓库。

externalThinking 于 8 月 11 日随 v17.2.14 加入。发布记录同时增加了 forceReasoningOff 和 disableReasoning，用于在 OpenAI 与 Azure OpenAI 路径上关闭原生推理。第二天的修复说明，Anthropic 与 Google 的部分接口起初没有真正关闭原生推理，可能导致模型在内部想一遍，又在 think 工具里写一遍。到本文核查时，最新版本已经是 v17.3.0，而不是 PDF 中的 v17.2.14。

当前源码还给出了三个关键细节：

  1. externalThinking 默认值是 false，不是安装后自动开启。
  2. 系统提示把 think 描述为“私有草稿，不向用户显示”。
  3. 工具实现同时标记 recorded: true。也就是说，它不出现在普通答案里，不代表它不会进入工具调用记录或会话存档。

这正是整件事最容易被标题遮住的地方。关闭“厂商原生推理”只是改变了模型把中间文字写到哪里，并没有让模型失去生成中间文字的能力。对于指令遵循能力强的模型，一个叫 think 的工具和一个足够复杂的任务，已经足以诱导它产生长篇工作草稿。

论文真正敲响的警报：你以为加密，就敢公开

论文团队从公开仓库抓取了 6,708 条智能体轨迹，共解析 315,320 个加密推理块。他们报告了 367 个个人身份信息条目和 182 份凭证。在确认属于真实用户会话的部分里，包括 62 个 API Key、33 个密码和 30 个个人邮箱。

这些数字最值得看的，不是“模型有没有秘密语言”，而是开发者的错误安全感：日志正文已经做过脱敏，加密块看起来又像一串不可读的 Base64，于是整个会话被提交到 GitHub、研究数据集或协作空间。可一旦加密块能被跨上下文读取，原本藏在里面的工具输出、环境信息和秘密就一起暴露。

论文也给了两个必须保留的限制。第一，实验针对 2026 年 7 月初可用的特定 API 与模型，厂商实现可以随时改变。第二，研究人员无法取得完整的原始明文作为地面真值，因此只能用 Token 数量、一致性和任务内容判断提取质量，不能证明每个字都与内部记录相同。

更关键的是，论文写明：团队在发布前向相关模型厂商、微软和 Hugging Face 做了负责披露；所有模型厂商确认收到报告，之后研究人员已经无法继续发动相同攻击。所以，把论文实验写成今天仍可直接复现的零日漏洞，也不准确。

外部草稿为什么仍然危险

加密推理块的漏洞被缓解，不代表外部草稿天然安全。恰恰相反，think 把原本由厂商控制的隐藏通道，变成了开发者自己负责的普通数据。

一段智能体任务通常会经过模型 API、代理框架、本地会话文件、终端渲染、遥测系统、错误追踪和第三方工具。只要其中一层默认保存工具参数，外部草稿就可能被复制多次。模型在分析代码时，还可能主动引用它刚看到的 .env 内容、数据库连接串、内部网址、客户姓名或 SSH 配置。

“私有”在这里往往只表示“不展示给终端用户”，不等于“不落盘、不上传、不备份、管理员也看不到”。如果团队把完整 Agent Trace 发给可观测平台，草稿可能已经离开本机；如果 CI 失败时自动附加会话上下文，它又可能进入工单；如果调试包被公开，风险就从一次请求扩散成长期可下载的数据副本。

这是一种典型的可观测性悖论：记录越完整，越容易定位模型为什么走错；记录越完整，也越容易把本来只出现一瞬间的秘密固化下来。看得见确实更容易控制，但前提是你先把它当作敏感数据，而不是免费附送的调试文本。

开发者现在该改什么

不需要等新的“越狱提示词”流出，下面这些动作今天就能做：

  1. 把推理块、思考签名和工具参数都视为敏感数据。 不要因为字段不可读或不会显示在 UI 中，就把它们当成无害元数据。
  2. 默认不记录完整的外部草稿参数。 对 think 工具，生产环境只保留调用是否发生、耗时、Token 数和错误码；确需排障时临时开启，设置短保留期和访问审计。
  3. 公开会话前做结构化剥离。 不只是正则替换 sk-，而是删除 reasoning block、signature、thought signature、工具参数和原始工具输出，再运行凭证扫描。
  4. 让智能体拿不到不必要的秘密。 用最小权限、短期令牌、隔离环境和按任务挂载，降低模型在草稿里复述长期凭证的机会。
  5. 检查日志的下一跳。 Sentry、Langfuse、OpenTelemetry、CI Artifact、客服工单、云端备份和团队聊天，都可能是“私有草稿”的真实落点。
  6. 已经公开过完整轨迹时，先轮换凭证。 删除仓库历史只能减少后续传播，不能证明旧副本没人下载。

对模型厂商来说，论文建议把加密信封绑定到用户、会话和对话位置，限制跨模型重放；对历史数据应轮换旧签名密钥，并拒绝继续解码旧格式。模型侧的拒绝训练只能作为第二道防线，不能替代加密上下文绑定。

最后的判断

如果把“攻破”理解为拿下服务器、窃取模型权重或直接读取神经网络底层状态，这次事件没有做到。Oh My Pi 的外部草稿也不能证明它逐字复现了原生隐藏思维链。

但如果问题换成“智能体会不会把分析过程里的秘密复制到更多系统”，答案已经很明确。论文从公开轨迹中找到了真实凭证；Oh My Pi 的功能又证明，只要提供一个普通工具，模型就愿意把大量中间文字写进开发者可记录的参数。

真正的边界不是“思考可见还是不可见”，而是谁能保存、搜索、转发和长期保留这些数据。 对普通开发者来说，最实用的结论不是研究怎么偷模型的草稿，而是回头检查自己的 Agent 日志：它们到底经过了几只手，又在哪些地方永远删不干净。
