# 正文图片与视频交付

文章原件和素材原件继续由内容库维护；不要手改公开快照或用压缩文件覆盖原图。

## 自动生成

`npm run build` 自动执行 `scripts/build-article-media.cjs`，只扫描已发布公开快照引用的站内媒体。

- 静态正文图片生成640、1280宽度的WebP展示版，不放大、不裁切；原图仍可点击查看。动图保持原格式。
- 视频生成首帧海报，使用浏览器原生控件、行内播放和按需加载，不自动播放、不抢占正文首屏带宽。
- 普通H264视频若索引在文件尾，生成无损索引前置副本，不重编码。
- 宽度超过1280且码率超过3Mbps的视频，额外生成720p网页播放版；高清原片不变，播放器下保留明确入口。低码率录屏不重复转码。
- 输出位于忽略入库的`public/media-previews/`与`lib/article-media.generated.json`。地址由内容哈希决定，资源变化才换地址，避免同网址缓存旧内容。
- 构建需要`ffmpeg`、`ffprobe`；部署流程会检查工具存在。

## 发布验收

- `npm run test:performance`：原件不变、幂等、路径隔离、图片响应式、原生视频属性和高清入口。
- `scripts/verify-article-media.cjs`：全部引用实际导出、视频索引前置、整站不超过10亿字节。超过容量时停止发布，不靠删除原件绕过。
- `scripts/verify-live.js`：线上全部素材可读，每个视频必须支持1024字节的206分段请求与正确的媒体类型。
- 浏览器需另验真实图片解码、桌面及窄屏布局、点击后播放时间推进；仅200状态或播放器外观不代表播放成功。

## 线路边界

现有素材优化不等于境内线路改造。全球CDN到境外托管仍可能受跨境网络影响，缓存命中也不能保证所有运营商可达。

不自动购买服务、不改域名解析、不改用户本机代理。外部多地区测速、备案或新托管服务须按用户授权另行处理。
