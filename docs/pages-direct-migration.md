# 官网直连 Pages 与独立留言接口

## 目标

- `hyphentech.top`：只解析到 GitHub Pages，网页、图片和视频不经过 Cloudflare 网页代理。
- `comments.hyphentech.top`：继续由现有 Cloudflare Worker 和原 D1 提供留言服务。
- 官网网址、文章标识、图片原件、验证码和管理凭据不变；不自动新增付费服务。

## 切换顺序

1. 在原 Worker 上增加接口自定义域名，保留旧同域路由，数据库不迁移。
2. 运行 `scripts/verify-comments-endpoint.cjs`，检查精确来源、预检、实时列表及拒绝未认证写入。
3. 发布引用新接口的前端、管理命令及只读预览；核实线上茶馆与文章留言。
4. 保存现有主站解析记录，核实 Pages 自定义域名和证书签发条件。
5. 证书不满足时，不把主站直接切到有证书错误的入口；需要维护窗口或新的用户决定时停止切换。
6. 切换解析后，GitHub 仓库变量 `BLOG_DELIVERY_MODE` 设置为 `direct`。默认值 `cloudflare` 用于迁移前及回退。
7. 直连模式等待新版构建可读，不再强制清 Cloudflare 页面缓存；必须确认页面无 Cloudflare 代理头且带 Pages 响应头。
8. 继续执行所有页面、附件、视频分段读取、链接、软件版本及独立留言接口的线上验收。

## 回退

先按切换前保存的记录恢复主站代理，再将 `BLOG_DELIVERY_MODE` 恢复为 `cloudflare`。
新版独立留言域名可以保留，前端不必为回退再次迁移数据库或更换凭据。
原缓存清除专用机密不删除、不扩权；代理模式继续使用现有选择性刷新及验收。

## 验收边界

命令行指定 `--noproxy` 只控制该命令，不代表已核实运营商出口，也不修改系统代理。
本机或部署服务器的成功结果不能替代国内多运营商、实体手机测试；按用户授权执行。
浏览器出现证书警告时不绕过，不以关闭证书校验代替修复。
