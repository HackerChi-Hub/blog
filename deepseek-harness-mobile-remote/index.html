电脑上的 AI 还在处理任务，人已经离开桌面。手机重新开一个聊天窗口，接不回原来的文件和执行记录。黑粉助手做的，就是给电脑上正在运行的 DeepSeek Harness 增加一个手机入口：用手机浏览器看原会话、继续发要求，任务仍由原电脑执行。

这篇从下载安装开始，走到手机真正收到回复。先用临时链接跑通，再按需要选择开放端口或动态域名。阿里云、腾讯云 DNSPod、Cloudflare 三家解析平台只需选自己正在使用的一家，不需要全部注册。

本文对应 黑粉助手 0.1.7 预览版，核对日期为 2026 年 10 月 24 日。云控制台图片采用三家官方帮助文档中的真实界面示例，阿里云部分为官方旧版界面；具体入口以文中的现行路径为准。

🎯 一、先准备什么：电脑能回答，再让手机连接

黑粉助手是独立辅助工具，由黑粉科技制作。 它连接官方 DeepSeek Harness，自己不提供模型，也不包含模型额度。你在原 Harness 中配置的模型、工作目录和会话会继续使用。模型请求的费用与数据流向，也继续由原配置决定。

黑粉助手自己的运行环境、临时通道和二维码组件已经放进安装包，不需要为了它再安装 Node.js 或通道工具。官方 Harness 仍需先安装、配置并在电脑上正常回复；原 Harness 所需的运行环境要按官方文档单独准备。

如果还没装 Harness，先打开DeepSeek Harness 官方中文说明，依照当前官方入口安装，完成模型设置。它还在开发者预览阶段，上游更新可能改变连接器兼容性；遇到挂载失败，先核对两边版本和发行说明，不要直接对正在执行任务的环境强制升级。

在电脑上选择一个不重要的测试会话，发送“只回复：电脑连接正常，不调用工具”。看到真实回复后，再做后面的远程连接。网页能打开、软件能启动和模型能回答，是三件不同的事。

下载适合自己系统的安装包

打开下载与更新：黑粉助手发行页，在附件中选安装包，别把 Source code 源码压缩包当成安装程序。

电脑系统 选择的文件 安装方式

🔍 二、三种方式怎么选：先想清楚谁来带路

把家里的电脑看成小区里的一户人家。域名解析相当于查地址簿，告诉手机该去哪个公网地址；端口映射像小区门口的分流，把某个门牌的访问送到屋内那台电脑；HTTPS 证书则帮助浏览器核对身份并加密路上的内容。三件事各有作用。

动态域名更新常写作 DDNS：家里的公网地址变了，程序替你更新地址簿。它不会替路由器开门，也不会自动给网页安装证书。域名在哪里买并不决定选哪家平台，看的是目前由谁负责这个域名的权威 DNS 解析。域名在阿里云买、解析转到 Cloudflare，就应选 Cloudflare。

连接方式 黑粉助手做什么 你需要准备什么 适合谁
临时链接 使用内置通道生成临时 HTTPS 入口 能访问通道服务的网络 第一次试用、短时间连接
开放端口 在电脑监听 HTTP 端口，保留配对认证 自行准备对外地址、端口映射；公网使用自行配置 HTTPS 已有域名、代理或现成网络入口
动态域名＋开放端口 开放端口，并定时更新所选平台的一条 A 记录 域名、平台凭据、可用公网入口、端口映射和外部 HTTPS 家庭公网地址会变，希望电脑自己更新解析

第三种方式可以接替树莓派或另一台机器上的动态域名更新程序，前提是原设备只承担这项任务。原设备若还做反向代理、证书续期或其他服务，仍需保留这些功能，或由你另外迁移。不要看到域名更新成功，就把整台旧设备关掉。

⚡ 三、先接入电脑上正在使用的 Harness

打开黑粉助手的“连接中心”。“内置运行环境”已就绪，表示助手自己的组件可用；“原 Harness 会话”已接入，才表示它接到了原来的工作区。

  1. 先保持官方 Harness 正常运行。

  2. 如果页面提供“接入已有 Harness”，点击它并刷新状态。这适用于已经存在可用连接器的环境。

  3. 第一次使用时，在“选择正在使用的配置”中选择当前 Harness 的配置，再点“挂载连接器”。多配置用户应选择自己实际工作时用的那一份。

  4. 等待 Harness 加载连接器，再刷新。若没有自动加载，等原任务空闲后重新打开 Harness。

  5. 看到“原 Harness 会话：已接入”后，再启动远程入口。

这里只给原工作区增加入口。正在运行任务时，先等任务到合适的停顿点，不为了刷新状态强行结束原进程。没有配置可选时，回到官方 Harness 完成首次启动，再回来刷新。

💰 四、方式一：临时链接，第一次使用先走这条

在左侧进入“远程入口”，连接方式选“临时链接 · 自动生成”，点击“保存连接方式”。返回“连接中心”，点击“启动远程连接”。入口就绪后，再点“生成配对二维码”。

用本人手机的系统浏览器打开扫码得到的完整链接。链接包含一次性配对信息，十分钟内有效，只能兑换一次。不要把它当成可以公开分享的普通网址；换另一个浏览器，也要分别配对。

进入手机页面，找到刚才的测试会话，发送“只回复：手机连接正常，不调用工具”。手机出现这条新消息的真实回复，才算完成这次连接。 电脑保持在线，模型和原 Harness 也要继续可用。

这张保留的网页验收图展示了应该核对的结果：新消息发出，模型确实返回对应回复。它来自 10 月 23 日的旧版独立网页验收，不能代替你在当前版本、当前网络上的测试；模型回复速度也不代表复杂任务的执行速度。

临时链接不用自备域名、不用配置路由器映射。流量经 Cloudflare 临时通道转发，网络必须能访问该服务；地址重新创建后可能变化，也没有持续可用保证。连接失败先看“检查与帮助”的入口检查结果，不要关闭配对或证书校验来凑成功。

🧩 五、方式二：开放端口，沿用自己已有的网络入口

如果你已经能从外网访问家里的电脑，这种方式最直接。进入“远程入口”，选“开放端口 · 自行配置对接”，主要填写三个项目。

项目 怎么填 示例的含义
监听地址 路由器直接转发到本机时通常用 0.0.0.0；同机反向代理可用 127.0.0.1 前者允许从电脑的网卡进入，后者只接收同一台电脑的访问
监听端口 选择未被占用的本机端口，默认 8767 这是黑粉助手 HTTP 服务的端口
外部访问地址 手机实际访问的完整地址，含协议，非默认端口要写端口 HTTPS 协议、ai.example.com 域名、19527 外网端口

完整填写示例（把域名替换成自己的）：

https://ai.example.com:19527

0.0.0.0 是监听设置，不能填进手机浏览器当访问地址。 127.0.0.1 是“这台设备自己”：手机访问它只会找手机自身。192.168.1.100 这类地址是局域网地址，离开家里的网络通常不能直接使用。

情况 A：路由器直接转发到黑粉助手

假设电脑局域网地址是 192.168.1.100，助手监听 0.0.0.0:8767，路由器可以设置“外网 TCP 端口 19527 → 192.168.1.100:8767”。不同路由器可能把入口叫作端口转发、虚拟服务器或 NAT 映射。建议给电脑做 DHCP 地址保留，避免重启后内网地址变化。

这条链路直接到的是 HTTP 服务，因此访问地址应当使用 HTTP 协议和实际外网端口，格式如下：

http://自己的公网地址或域名:19527

仅做端口转发，不能把 http 改成 https 就得到加密连接。 为了保护公网访问中的会话和配对信息，应先在外部部署 HTTPS，再使用它；这段直接 HTTP 的说明用于认清端口关系，不建议拿它作为长期公网入口。

情况 B：已有 HTTPS 代理和证书

假设同一台电脑上已有 HTTPS 服务监听 19527，并把请求转到 http://127.0.0.1:8767。此时助手可以监听 127.0.0.1:8767，外部访问地址填写下面的 HTTPS 示例；路由器映射的目标则是电脑上的 HTTPS 监听端口 19527。

https://ai.example.com:19527

完整顺序是：手机 → 域名对应的公网地址:19527 → 路由器 → 外部 HTTPS 服务:19527 → 黑粉助手 HTTP:8767 → 原 Harness。如果代理在另一台设备上，助手要监听那台代理能访问到的网卡地址；代理目标不能继续填另一台设备自己的 127.0.0.1。

代理需要保留网页和 WebSocket 连接。证书必须覆盖手机访问的域名，并由浏览器正常信任；申请、私钥保存、代理配置及自动续期，都由你原来的外部方案负责。黑粉助手不导入证书，也不接管续期。

保存设置，回“连接中心”启动，再生成二维码。公网验证时，让手机关闭 Wi-Fi、使用移动网络访问；这能排除“只在家里 Wi-Fi 下能用”的误判。若同一 Wi-Fi 下反而打不开公网域名，可能与路由器的回流访问能力有关，需要分别验证内外网络。

🚀 六、方式三：动态域名＋开放端口，让电脑更新地址簿

第三种方式在上一节的网络链路上，增加自动更新 DNS。先让开放端口和外部 HTTPS 能正常工作，再加入动态域名，排查会简单很多。

在自己的解析平台中，先手动建立一条供手机访问的 A 记录。这里统一举例：根域名 example.com，主机记录 ai，组合后是 ai.example.com。

A 记录填写家中实际公网 IPv4；它只存地址，不填写 https、端口或网址路径。example.com 和文中的内网地址均为示例，要换成自己的值。

如果想直接使用 example.com，主机记录填写 @。阿里云和腾讯云这条记录选择默认线路；Cloudflare 要确保该完整主机名下只有一条 A 记录。助手只更新已有的唯一记录，不会自动建域名或创建记录；重复记录、未启用记录等情况需要先在云端整理。

在“远程入口”选“动态域名＋开放端口”。监听地址、监听端口、外部访问地址沿用上一节的实际链路；然后选择解析平台、填写根域名与主机记录，导入对应凭据。

公网地址检测可选择“国内检测源 · 双源核对”。两个来源都成功且结果一致才会更新；检测失败或结果不同，就停止本次更新。开启代理时，尤其要核对检测结果是否等于家中路由器的公网 IPv4，不能把代理服务器出口写进家里的域名。

“路由器公网 IPv4（选填）”通常留空，让程序自动检测。手动填写后会固定使用该值，适合你明确知道应写哪个地址的情况；家庭公网地址变化时，它不会替你修正这个手填值。

先点“保存连接方式”，再点“检查解析配置（不修改记录）”。检查会读取云端记录，显示记录是否存在、检测地址是否一致；检查按钮也会校验并保存有效的本机表单设置，不向云端写入解析记录。检查通过后回首页启动连接，启动时同步一次，随后每五分钟检查；地址没有变化就不重复写。

DDNS 能更新域名，不能穿透运营商内网。若路由器 WAN 地址属于运营商内网、存在多级 NAT，或入站端口被运营商限制，仅添加域名和映射仍可能无法从公网进入。这时可先用临时链接，或由自己另行安排能入站的网络方案。当前动态更新针对 IPv4 A 记录，不负责 AAAA 记录。

🧠 七、阿里云：创建专用 RAM 用户，下载 AccessKey 文件

先确认域名的解析确实由阿里云管理。打开阿里云 RAM 控制台，用有权限的管理员操作。RAM 用户就像给应用单独发的工作证：只让它查和改指定域名，避免把整个云账号的钥匙交给软件。

  1. 在“身份管理 → 用户”创建专用用户，例如 hyphen-ddns。

  2. 选择给程序使用的永久 AccessKey 访问方式；只用于助手的账号通常不需要控制台登录。

  3. 在“权限管理 → 权限策略”创建自定义策略，切到脚本编辑，将操作限定为 DescribeDomainRecords 与 UpdateDomainRecord，将资源限定到自己的目标域名。

  4. 回到该 RAM 用户的“新增授权”，选择刚创建的自定义策略并确认绑定。创建了策略但没有绑定，程序仍然没有权限。

  5. 进入该用户的“凭证管理”中创建 AccessKey，按页面完成验证。Secret 只在创建时显示一次，立即下载 CSV 文件并妥善保存。

上图是阿里云官方旧版安全提示，帮助识别子用户入口。当前路径按创建 RAM 用户和创建 AccessKey核对。

不要给助手绑定 AdministratorAccess 或 AliyunRAMFullAccess；这些是管理云账号或身份的权限，并非更新解析所需。

可从下面的最小操作集合开始，把 ACCOUNT_ID 和 example.com 换成资源所属的阿里云账号 ID 与实际根域名。

域名级权限不等于限制到 ai 这一条记录，助手自身才会筛选所填的主机记录。

{
  "Version": "1",
  "Statement": [{
    "Effect": "Allow",
    "Action": [
      "alidns:DescribeDomainRecords",
      "alidns:UpdateDomainRecord"
    ],
    "Resource": ["acs:alidns:*:ACCOUNT_ID:domain/example.com"]
  }]
}

资源 ARN 的生成与具体接口授权，以阿里云 DNS 自定义权限示例和接口授权信息为准。

若控制台校验要求调整资源写法，使用资源选择器生成的目标域名 ARN；不通过加管理员权限来掩盖资源范围填错。这个工作用户不需要额外管理其他 RAM 用户，也不需要证书权限。

官方提供的“下载 CSV 文件”可以省掉手工抄写。软件导入用的两列是 AccessKey ID 和 AccessKey Secret。若下载内容不符合下列单组格式，整理成对应 CSV 或 JSON 后再导入；不要上传整份多账号凭据清单。

AccessKey ID,AccessKey Secret
替换为自己的AccessKeyID,替换为自己的AccessKeySecret

也可以保存下面的 JSON。这里是凭据文件，和上面的权限策略文件作用不同；权限策略放进 RAM 控制台，凭据文件才导入黑粉助手。

{"provider":"aliyun","AccessKeyId":"自己的AccessKeyID","AccessKeySecret":"自己的AccessKeySecret"}

在助手选择“阿里云 → 导入密钥文件”，选 CSV 或 JSON，看到导入成功后点保存。文件导入只省去填写文字，不会替你在阿里云创建用户或授权。

阿里云关于下载与一次性显示的说明见官方创建与保存教程。当前助手不支持 STS 临时凭据。

📉 八、腾讯云 DNSPod：用腾讯云 API 密钥，不用旧版令牌

打开腾讯云访问管理 CAM，创建专用于动态域名的子用户，选择程序访问。不要把主账号密钥交给助手，也不要在旧版 DNSPod 令牌页找 ID／Token；当前实现调用的是腾讯云 API 3.0，需要一对 SecretId 和 SecretKey。

先给子用户绑定域名权限

在 CAM“策略”中新建自定义策略，使用策略生成器或按语法创建。选 DNSPod 服务，只保留 DescribeRecordList（查询记录）与 ModifyDynamicDNS（更新动态记录），资源选择目标域名，再把策略关联到刚才的子用户。

需要准备的值 在哪里找 用途
主账号 UIN 腾讯云账号信息页 权限策略中资源的所属账号
DomainId DNSPod 域名详情，或由管理员调用 DescribeDomain 查询 限定授权的域名资源；不是 A 记录的 RecordId
根域名 DNSPod 中实际托管的域名 填进助手根域名一栏

下面是按腾讯云授权语法与资源类型说明收窄操作的示例。替换 OWNER_UIN 与 DOMAIN_ID，不要原样保存占位符。

{
  "version": "2.0",
  "statement": [{
    "effect": "allow",
    "action": [
      "name/dnspod:DescribeRecordList",
      "name/dnspod:ModifyDynamicDNS"
    ],
    "resource": ["qcs::dnspod::uin/OWNER_UIN:domain/DOMAIN_ID"]
  }]
}

QcloudDNSPodFullAccess 是更宽的 DNSPod 全读写系统策略，包含更多资源和操作，不是这两个接口的最小授权。只读策略则不能完成地址更新。权限是否在真实账户中生效，需要用助手检查及后续实际更新核实，不能仅凭策略保存成功判断。

再创建并保存 API 密钥

进入“用户列表 → 目标子用户 → API 密钥”，点击“新建密钥”，按页面完成验证。立即保存 SecretId 与 SecretKey，SecretKey 后续无法再次查询。

具体路径见腾讯云子账号密钥管理。

如果创建页提供下载，保存后先核对表头；也可将这对值保存成下面的一组 CSV。不是把腾讯云登录密码填进文件，也不是导入 CAM 权限策略。

SecretId,SecretKey
替换为自己的SecretId,替换为自己的SecretKey

JSON 格式同样可用：

{"provider":"tencent","SecretId":"自己的SecretId","SecretKey":"自己的SecretKey"}

回黑粉助手，平台选“腾讯云 DNSPod”，根域名填 example.com、主机记录填 ai，导入、保存、检查。DNSPod 中要已有默认线路的那条 A 记录。

助手调用的动态更新接口不需要填写地域，界面也无需额外选择广州或上海。

🎯 九、Cloudflare：创建限定区域的 API Token

先在Cloudflare 控制台确认域名区域已经激活、权威解析确实交给 Cloudflare。在它的 DNS 记录页面先建好 ai 对应的唯一 A 记录。

进入“我的个人资料 → API 令牌”，点“创建令牌”，使用“编辑区域 DNS”（Edit zone DNS）模板或自定义令牌。英文界面可按下面的字段对应操作。

控制台项目 应怎样选择 为什么
Permissions Zone → DNS → Edit 读取、列出并更新 DNS 记录；编辑权限包含相应读取能力
Zone Resources Include → Specific zone → 自己的 example.com 只让令牌操作这个域名区域
Zone → Zone → Read 自动查找区域时增加；手填 Zone ID 可不加 让助手能按根域名找到区域
Client IP Address Filtering 确定出口稳定时才设置 家庭出口会变，绑死旧地址会导致后续调用失败
TTL／有效期 按自己的轮换计划设置 这是令牌有效期，和 DNS 记录缓存时间不是一回事

官方示例图的资源处显示 All zones，仅用来识别页面位置。实际配置应改成 Specific zone，选自己的域名。 图片中的 Zone Read 对应自动查找区域；若希望减少这项权限，自己填写 Zone ID。

点“继续到摘要”，检查授权域名与操作范围，再创建令牌。复制并安全保存令牌值，它只在创建完成时展示一次。不要复制整个 curl 测试命令，也不要使用 Global API Key。

官方令牌创建说明提供了当前字段和完整流程。

Zone ID 是这块域名区域的编号，通常为 32 位十六进制字符串。

在该域名的概览页 API 区域查找；当前界面也可按官方账号与区域 ID 指南操作。不要把 Account ID 填进 Zone ID。

最省事的文件是 TXT：只放令牌本身一行，不加引号、不加“Token=”前缀。选择 UTF-8 纯文本保存，别保存成 Word 文档或富文本文件。若同时导入 Zone ID，可用 JSON：

{
  "provider": "cloudflare",
  "apiToken": "自己的APIToken",
  "zoneId": "替换为自己的32位ZoneID"
}

上面的 zoneId 是说明占位符，必须替换成真实 32 位值；如果让助手自动查找，直接删除整个 zoneId 字段，并确保令牌有 Zone Read 权限。也支持两列 CSV：

APIToken,ZoneId
替换为自己的APIToken,替换为自己的32位ZoneID

导入后保存并检查。使用 19527 这类自定义公网端口时，要注意 Cloudflare 的橙云代理并不支持任意端口。只需域名解析时，可以自行把该记录设为“仅 DNS”；若要使用代理，则自行选择官方支持的端口与方案。

仅 DNS 不会自动给你的电脑提供 HTTPS，证书仍由外部方案负责。助手更新记录时保留已有代理开关和 TTL，不替你切换橙云或灰云。

🔍 十、文件导入、保存、更换和清除，到底有什么区别

三家平台统一按这个顺序操作：选平台 → 填域名和主机记录 → 导入对应凭据文件 → 保存连接方式 → 检查解析配置 → 启动连接 → 手机验证。

导入后字段内容会隐藏，界面提示“凭据已导入”。此时只是填入当前表单；点击保存后才写入本机。页面没有明文回显，不代表文件没读进去。保存后显示“已保存，无需重复填写”，表示同平台的旧凭据仍在；把输入框留空会继续使用它。

想做的事 正确操作
首次添加凭据 导入或填写后点保存，随后检查
更换阿里云／腾讯云成对密钥 两项一起更换，或导入新文件后保存
连接运行中修改参数 先点“停止连接并修改配置”，手机会断开，原 Harness 任务继续
忘记本机保存的旧凭据 点“清除已保存密钥”并确认，再导入新凭据
从阿里云换到 Cloudflare 切平台后重新导入该平台凭据，不会混用旧平台密钥
彻底停用泄露的凭据 除了本机清除，还要去云平台禁用或撤销那一把密钥

清除本机密钥会保留域名和监听参数，不删除云端记录，不修改证书，也不撤销云平台的密钥。原来的 CSV／JSON／TXT 仍在你保存的位置；导入操作不上传原文件，也不把原文件另复制进应用目录，但保存后的凭据会保留在本机私有配置中。请保护电脑账户和备份，别把密钥文件放进公共网盘或代码仓库。

每次只导入一组凭据，文件不超过 64KB。多账号文件、重复字段、平台不匹配会被拒绝。本文文件示例里的中文占位符不能用来连接真实平台；证书的 fullchain.pem、privkey.pem 也不是这里的凭据文件。

⚡ 十一、从“显示已启动”走到真正可用

使用临时链接时，检查通道就绪后配对即可；使用自己的域名时，按下面顺序核对，哪一步不通过就先处理哪一层。

  1. 电脑本机的原 Harness 能收到模型回复。

  2. 助手显示原会话已接入，网关已启动。

  3. 动态域名模式能查到唯一 A 记录，检测公网地址与路由器一致。云平台确认记录值正确；旧 DNS 缓存可能还需要等待 TTL。

  4. 手机使用移动网络能打开外部 HTTPS 地址，浏览器没有证书错误。

  5. 使用新生成的完整配对链接，在有效期内完成配对。

  6. 手机上进入原测试会话，发“只回复：手机连接正常，不调用工具”，等到新回复。

  7. 刷新手机页面，再发一条简单消息，确认不是只打开了静态页面。

若从其他设备迁移 DDNS，先记录旧配置，确认助手已经查到正确记录、完成启动同步和下一轮五分钟检查，再停用旧设备上更新同一条记录的程序。两套程序同时维护同一条记录，尤其检测到不同出口时，可能来回覆盖。证书续期等其他服务继续按原方案运行。

当前版本的三系统构建与安装启动检查已经通过；阿里云已有真实环境的解析更新、恢复及消息收发记录。

腾讯云和 Cloudflare 完成的是官方接口与签名对照、隔离模拟接口及导入界面验收，没有用真实云账户执行 DNS 写入。 各家的账号权限、套餐、网络与最终解析效果，仍应按上面的顺序在自己的环境核实。

💰 十二、日常怎么用：保留电脑任务，管好手机入口

关闭黑粉助手窗口会保留后台连接；停止助手连接会断开手机，不会停止电脑上的原任务。要让连接恢复，重新启动入口并按需要配对。电脑休眠、关机、Harness 退出或模型服务不可用时，手机端也无法继续正常工作。

配对后的手机可以继续操作原会话，优先用本人设备与可信浏览器。截图、直播或分享演示时，隐藏完整二维码、配对链接、云平台密钥和私人会话。有人拿到配对信息或密钥时，要分别撤销手机登录与云平台凭据，不能只删除一张截图。

“检查与帮助”中的“提升使用体验”可以关闭匿名统计。统计范围是产品隔离后的设备标识、版本、系统与架构，不采集会话、指令、文件或密钥；具体范围可展开隐私说明查看。需要根据这些信息排查版本问题时，先检查这里的说明。

最容易复现的上手顺序是：先让电脑回复，再用临时链接让手机收到回复；已有公网入口就切开放端口，需要跟随家庭公网地址变化再开动态域名。 你可以根据自己的网络停在任意一条路线，不必为了使用手机入口而把三家云平台都配置一遍。
