DeepSeek静默换代，0813到底发布了吗？

API 已经换上新版本，网页端、App 和开放权重却仍是三个问号。真正值得盯住的，不是名字变了，而是低价代码 Agent 能力开始进入开发者工作流。
🗓
2026年8月13日·黑粉科技

▍🎯 没有独立公告，API 却已经换了

2026 年 8 月 13 日，DeepSeek 的稳定模型名 `deepseek-v4-pro` 已经指向 `DeepSeek-V4-Pro-0813`，原来的调用方法不用改。

官网没有单独挂出一篇以 0813 命名的公告，更新日志里也还停在此前的节点。它不是“即将可用”，而是已经藏在稳定接口后面运行。

这件事最容易被一句“DeepSeek 发布新模型”糊成一团。准确状态其实分成三层：API 已切换；网页版和 App 是否切换，没有明确结论；0813 对应的开放权重是否上线，同样没有确认。服务端更新、消费端更新和权重开放，从来不是同一个开关。

// **能调用，不等于网页端已换；能调用，也不等于权重已开。**

时间线也能说明这种错位。2026 年 4 月 24 日，V4 预览版公开；7 月 31 日，V4 Flash 0731 正式版进入 API，当时 Pro 与 App/Web 保持不变。

8 月 12 日，OpenRouter 建立 0813 端点；到了 8 月 13 日，DeepSeek 的稳定接口才明确完成映射。

状态当前能确认什么仍不能确认什么
官方 APIdeepseek-v4-pro 已映射到 0813底层改动细节
网页版与 App现有服务仍可访问是否已经使用 0813
开放权重此前 V4 Pro 权重仍在是否已经同步 0813

※ 三种状态必须分开判断，不能由 API 映射反推其他端点。

这张表的要害，是把“发布”从一个营销词拆成可核验的工程状态。开发者今天就能切换接口测试；普通用户却无法仅凭聊天体验确认版本；本地部署者更不能把旧仓库改个文件名，就当自己拿到了 0813。名字可以一夜更新，证据链不能跟着脑补。

▍⚡ 百万上下文没缩水，真正变化指向代码 Agent

0813 延续了相当激进的服务规格：1M 上下文，也就是 1,048,576 token；最大输出达到 384K token。它同时提供非思考与思考模式，思考默认开启，默认强度为 high。JSON Output、工具调用、对话前缀续写和 FIM 补全也在支持范围内。

规格没有突然换一副骨架。此前 V4 预览版资料描述的 Pro 是混合专家模型，拥有 1.6T 总参数，每个 token 激活 49B 参数，预训练数据超过 32T token。在 1M 场景下，它的单 token 推理 FLOPs 为 V3.2 的 27%，KV cache 为后者的 10%。

这些架构数字属于此前公开的 V4 资料，并不是 0813 独有的新技术报告。当前没有新文件证明参数量、训练数据或注意力架构发生变化。因此，更稳妥的判断是：0813 像一次后训练与工具使用能力的集中加固，而不是底座推倒重来。版本号变了，不能顺手把旧架构资料包装成新突破。

OpenRouter 页面列出的厂商成绩，确实把升级方向写得很直白。DeepSWE 从 12.8 到 62.7，CyberGym 从 52.7 到 83.3，NL2Repo 从 38.5 到 61.5，Terminal Bench 2.1 从 72.1 到 87.9。提升集中在仓库、终端、安全与长链路任务。

另外两项也延续了同一方向：DSBench-Hard 从 31.1 到 67.2，AutomationBench Public 从 12.8 到 31.8。可是这些仍是平台列出的厂商成绩，测试环境可能不同，也缺少大规模独立复测。它们足以指认发力方向，不足以证明全面碾压。

▍🧩 Responses API 能接 Codex，但兼容层藏着坑

对写软件的人来说，0813 最有含金量的变化不是聊天更顺，而是能通过 Responses API 接入 Codex。`input`、`instructions`、流式返回、`max_output_tokens`、函数工具、服务端联网搜索、`tool_choice` 和 `reasoning.effort` 都能使用。

Codex 所需的 `apply_patch` 自定义工具也已经兼容，这意味着它不只会回答代码问题，还能进入真实仓库修改文件。思考强度允许 none、low、high、max；none 会关闭思考。对于仓库级任务，这条接入路径比单纯换一个聊天模型实在得多。

// 兼容接口最危险的地方，往往不是报错，而是假装听懂。

坑也埋在“部分兼容”四个字里。`previous_response_id` 与 `conversation` 不支持，服务仍然无状态；`store`、后台任务、MCP、计算机操作、文件检索和代码解释器也没有真正接通。现有应用若依赖这些能力，换基础地址并不能完成迁移。

更麻烦的是，一部分参数不会直接报错，而是被忽略。`verbosity` 不生效，`reasoning.summary` 不会返回摘要，`parallel_tool_calls` 会被忽略，因为并行工具调用始终开启。图片块也不会进入视觉模型，只会被替换成占位文本。程序没崩，不代表功能没丢。

思考模式还有一个容易漏掉的工程细节：工具调用发生后，下一轮回传工具结果时，需要保留这一轮的 `reasoning_content`。

与此同时，temperature、top_p、presence_penalty 和 frequency_penalty 在思考模式下不生效。旧客户端照常传参，模型却可能完全不理。

▍💰 低价不是慈善，而是抢开发者入口

中国区单价目前没有随 0813 上调。每百万 token，缓存命中输入是 0.025 元，未命中输入是 3 元，输出是 6 元。按当前单价计算，输入 100 万 token 且未命中缓存，再输出 10 万 token，费用约为 3.6 元。

如果那 100 万输入全部命中缓存，同样输出 10 万 token，费用约为 0.625 元。国际页面对应的输入缓存价、未命中输入价和输出价，分别是 0.003625 美元、0.435 美元与 0.87 美元。长上下文一旦能复用，成本差距会被迅速放大。低价的真正目标，是让开发者懒得再换接口。

这很像安卓当年用免费开放换取生态入口：先让开发者、厂商和工具链围着自己生长，再从规模里获得议价权。不同之处在于，模型调用持续消耗算力，边际成本并不会凭空消失。DeepSeek 已经明确提示近期可能整体提价，而且预计涨幅较大。

因此，眼前价格更像一张生态入场券，而不是永久合同。第一阶效应是代码工具降低调用成本；第二阶效应是更多插件与客户端围绕兼容接口适配；再往后，迁移成本上升，稳定接口就会变成开发者默认入口。先把互补品做成白菜价，是平台竞争的老手艺。

V4 Pro 的官方并发限制是 500，V4 Flash 则是 2500，这也说明两者承担的角色不同。Pro 更像高能力、长链路任务的主力，Flash 更适合吞吐更高的调用。只盯单价，不看并发、延迟、推理 token 和失败重试，账单很容易算得过于乐观。

▍🔒 API先走，本地部署者先别急着认领0813

官方 Hugging Face 仓库目前仍把 DeepSeek-V4-Pro 描述为 V4 预览版，仓库存储量约 864.8GB。模型 API 元数据显示，最后修改时间是 2026 年 6 月 22 日，早于 0813 进入服务端。当前公开权重与新接口版本之间，缺少一条可核验的同步记录。

// **开放过 V4 Pro，不等于已经开放 V4 Pro 0813。**

这对本地部署者不是咬文嚼字。你下载到自己机器上的，决定了隐私、可复现性、量化兼容和推理框架适配；服务端稳定名背后的权重，则可以随平台更新。两者名字相近，控制权却完全不同。一个归你保管，一个只允许你调用。

所以现在最合理的分工很明确：做代码 Agent 的人，先用 `deepseek-v4-pro` 跑真实仓库任务，记录成功率、工具回合和费用；等本地部署的人，继续核对仓库提交、模型卡和文件变化。不要把此前权重重命名成 0813，也别拿服务端成绩替本地版本背书。

普通用户则不用急着猜网页端是不是偷偷换了。没有版本标识、变更记录或可复现对照，单凭“感觉更聪明”没有判断价值。真正能带走的动作，是把自己的仓库任务固定下来：同一代码、同一指令、同一工具权限，比较 0813 的完成质量与实际账单。

📌
0813已经可用，但还不能被说成全面发布 DeepSeek-V4-Pro-0813 已经进入官方 API，百万上下文、384K 最大输出和当前低价都能直接使用，代码 Agent 与 Codex 接入是最值得验证的方向。但网页版、App、开放权重和独立复测仍有明确空白。想试就用稳定模型名跑真实仓库，并把失败日志、工具回合和费用留下；想本地跑就盯住仓库提交，别给旧权重提前戴新帽子。我的判断很直接：接口已经开门，生态争夺已经开打，只有“全面发布”这四个字还没有拿到全部证据。
